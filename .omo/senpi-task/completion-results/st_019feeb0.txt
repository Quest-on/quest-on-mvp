I read this as a research deliverable - I’ll distinguish first-party documentation from inference and third-party reporting, then compare the systems and extract professor-memory design lessons.

# Personal memory in major AI assistants

**Evidence scope:** Public product documentation and announcements available for the 2025+ memory generation. Some first-party pages are living documents and may describe newer behavior than the original launch. **DOCUMENTED** means stated by the vendor; **INFERRED** means an architectural conclusion not confirmed by the vendor; **THIRD-PARTY** means press reporting.

## 1. OpenAI ChatGPT

### Saved memories versus reference chat history

**DOCUMENTED — 2025 two-layer model**

- **Reference saved memories** are durable facts the user explicitly asked ChatGPT to retain—name, favorite color, dietary requirements—or that ChatGPT judged useful enough to save automatically. They are stored separately from chat history and remain until deleted. ([Saved-memory reference](https://help.openai.com/en/articles/11146739-how-does-reference-saved-memories-work), [Memory FAQ](https://help.openai.com/en/articles/8590148-memory-faq))
- **Reference chat history** lets ChatGPT derive useful interests and preferences from previous conversations without representing every detail as a permanent saved-memory item. These details can change as ChatGPT revises what is useful; OpenAI explicitly advises saved memory for information that must always remain top-of-mind. ([Saved-memory reference](https://help.openai.com/en/articles/11146739-how-does-reference-saved-memories-work))
- A deleted chat does not by itself delete a saved memory extracted from it. Full erasure requires deleting both the memory and the source chat; newer memory may additionally require removing files, archived chats and connected-app sources. ([Memory FAQ](https://help.openai.com/en/articles/8590148-memory-faq))

**DOCUMENTED — newer evolution**

OpenAI’s current FAQ describes an “improved memory” as a continually updated synthesis from chats, files and connected apps, exposed through an editable **memory summary**. The summary is explicitly incomplete: it is a high-level view and may omit less relevant details even though they can still influence personalization. Users may revert to the legacy saved-memory system. ([Memory FAQ](https://help.openai.com/en/articles/8590148-memory-faq))

### Extraction, writing and stale/conflicting information

**DOCUMENTED**

- Explicit write: “Remember that I am vegetarian…” creates a saved memory. ([Memory FAQ](https://help.openai.com/en/articles/8590148-memory-faq))
- Implicit write: ChatGPT may save information it predicts will be useful without a direct request. ([Memory FAQ](https://help.openai.com/en/articles/8590148-memory-faq))
- The model may update, combine or remove saved memories when asked. Newer memory updates automatically and was introduced partly because legacy memories became stale or contradictory—for example, “training for a marathon” versus “sprained my ankle.” ([Memory FAQ](https://help.openai.com/en/articles/8590148-memory-faq))
- OpenAI says it has trained ChatGPT not to proactively remember sensitive information such as health details unless explicitly requested, but also warns that sensitive information can appear if users share it; therefore this is a model-behavior mitigation, not a hard storage prohibition. ([Memory FAQ](https://help.openai.com/en/articles/8590148-memory-faq))

**INFERRED**

- Extraction is model-mediated semantic synthesis rather than deterministic field extraction. OpenAI does not publish schemas, confidence thresholds, deduplication algorithms or conflict-resolution precedence. The documented ability to synthesize, combine and prioritize supports this inference, but not a more specific architecture. ([Memory FAQ](https://help.openai.com/en/articles/8590148-memory-faq))

### Retrieval at inference time

**DOCUMENTED**

- Saved memories operate similarly to custom instructions and form part of the context used to generate a response; legacy saved memories are “always considered” until deleted. ([Memory FAQ](https://help.openai.com/en/articles/8590148-memory-faq))
- With chat-history reference, relevant information from prior conversations may be introduced into new chats. ChatGPT does not retrieve every detail. ([Saved-memory reference](https://help.openai.com/en/articles/11146739-how-does-reference-saved-memories-work))
- Newer UI can show sources used for personalization—custom instructions, chats, files and memories—and explain why a memory was used, although OpenAI warns the source display may not show every factor. ([Memory FAQ](https://help.openai.com/en/articles/8590148-memory-faq))
- Within non-enterprise projects, ChatGPT prioritizes project chats and files when answering; project-only memory imposes a hard source boundary. ([Projects](https://help.openai.com/en/articles/10169521-using-projects-in-chatgpt))

**NOT DOCUMENTED**

OpenAI does not disclose whether retrieval uses embeddings, keyword search, recency scoring, memory importance scores, a separate retrieval model or a fixed token budget. Claims about those mechanisms should be labeled inference, not product fact.

### User control, deletion and Temporary Chat

**DOCUMENTED**

- Users can ask “What do you remember about me?”, explicitly correct/forget information, edit the memory summary, delete individual/all memories, or disable memory. ([Memory FAQ](https://help.openai.com/en/articles/8590148-memory-faq))
- Deleted saved memories may remain in safety/debug logs for up to 30 days. Removing a memory does not rewrite mentions already present in old chat transcripts. ([Memory FAQ](https://help.openai.com/en/articles/8590148-memory-faq))
- Disabling memory is not necessarily deletion: old saved memories remain unless separately removed. If memory is re-enabled while old source chats remain, ChatGPT may learn from those chats again. ([Memory FAQ](https://help.openai.com/en/articles/8590148-memory-faq))
- **Temporary Chat** does not access or create personalization memories, does not appear in history and is not used for model training; OpenAI may retain a copy for up to 30 days. Custom instructions still apply. Limited prior context may still be used in rare safety/security cases, so Temporary Chat is not an absolute “no contextual processing” guarantee. ([Temporary Chat FAQ](https://help.openai.com/en/articles/8914046-temporary-chat-faq))

### Projects and boundaries

**DOCUMENTED**

- At project creation, users choose **default** or **project-only** memory; existing default projects cannot simply be converted—users must create a new project. ([Projects](https://help.openai.com/en/articles/10169521-using-projects-in-chatgpt))
- Project-only memory does not reference account saved memories, allows retrieval from chats inside that project, and blocks chats outside it. Shared projects become permanently project-only and cannot access members’ personal context, custom instructions or outside memories. ([Projects](https://help.openai.com/en/articles/10169521-using-projects-in-chatgpt))
- Default behavior differs by plan: Enterprise/Edu project chats remain contained; non-enterprise default projects can reference outside chats unless a project-only boundary prevents it. ([Projects](https://help.openai.com/en/articles/10169521-using-projects-in-chatgpt))
- Project memory has no personal-memory-style list of individual project memories; it operates through the project’s conversations and resources. ([Projects](https://help.openai.com/en/articles/10169521-using-projects-in-chatgpt))

### Enterprise/admin

Workspace controls can disable memory and other tools across projects; retention, residency, audit and access rules inherit workspace policy. Business/Enterprise/Edu project information is not used for model training by default. ([Projects](https://help.openai.com/en/articles/10169521-using-projects-in-chatgpt), [Enterprise privacy](https://openai.com/enterprise-privacy/))

## 2. Anthropic Claude

### Consumer Claude memory

**DOCUMENTED**

- Anthropic launched Claude memory in September 2025 for Team/Enterprise and extended it to Pro/Max in October. It is explicitly optional and enabled from Settings. ([Anthropic announcement](https://claude.com/blog/memory))
- At initial setup, Claude generates memory from existing chats. The retained representation presented to users is a single **memory summary**, not a ChatGPT-style list of atomic saved-memory cards. ([Anthropic announcement](https://claude.com/blog/memory))
- The summary is directly visible; users update it conversationally and can tell Claude what to focus on or ignore. ([Anthropic announcement](https://claude.com/blog/memory))
- Each project gets a separate memory, intended to isolate different clients, confidential work and concurrent initiatives. ([Anthropic announcement](https://claude.com/blog/memory))
- **Incognito chat** starts with a clean slate, does not appear in conversation history and does not read or write memory; ordinary memory/history remains unchanged. ([Anthropic announcement](https://claude.com/blog/memory))
- Enterprise admins can disable memory for the organization. Team/Enterprise standard retention settings continue to apply. ([Anthropic announcement](https://claude.com/blog/memory))

**INFERRED**

- Because Anthropic exposes one generated summary and says Claude adjusts it based on focus/ignore instructions, consumer Claude likely performs periodic or event-driven summarization rather than maintaining only independent fact records. Anthropic has not documented update frequency, confidence scoring, conflict precedence or whether additional hidden memory exists beyond the visible summary. ([Anthropic announcement](https://claude.com/blog/memory))

### Memory tool: separate developer primitive

The **Claude Platform memory tool must not be presented as the implementation contract for claude.ai memory**.

**DOCUMENTED**

- It is a client-side tool through which Claude requests persistent file operations. The host application—not Anthropic—stores and serves memory. ([Memory tool docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool))
- Claude automatically checks `/memories` before a task and may create/read/update/delete files during work. Retrieval is just-in-time, avoiding loading all memory into the context window. ([Memory tool docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool))
- Developers control namespace, storage, expiry and security. Anthropic recommends coherent/up-to-date files, deleting obsolete material, constraining what gets written, size caps and strict path traversal protection. ([Memory tool docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool))

### Difference from ChatGPT

- **Claude:** project separation is the organizing principle and the visible representation is a project-specific summary. ([Anthropic announcement](https://claude.com/blog/memory))
- **ChatGPT:** historically exposes durable atomic saved facts plus a more fluid chat-history layer; project-only memory is optional rather than inherent to every project. ([Saved-memory reference](https://help.openai.com/en/articles/11146739-how-does-reference-saved-memories-work), [Projects](https://help.openai.com/en/articles/10169521-using-projects-in-chatgpt))
- **Claude gives stronger visible summary editing; ChatGPT gives stronger atomic-memory deletion in its legacy mode.** Newer ChatGPT memory is converging toward Claude’s synthesized-summary model. ([Anthropic announcement](https://claude.com/blog/memory), [OpenAI Memory FAQ](https://help.openai.com/en/articles/8590148-memory-faq))

## 3. Google Gemini personal context

### Data sources and granularity

**DOCUMENTED**

1. **Saved info:** explicit durable details such as dietary restrictions, interests or a partner’s name. ([Google announcement](https://blog.google/products-and-platforms/products/gemini/gemini-personalization/), [personalization help](https://support.google.com/gemini/answer/15637730?hl=en))
2. **Past chats:** Gemini can derive relevant context from previous Gemini conversations. This first appeared for Advanced users and was announced for broader rollout. ([Google announcement](https://blog.google/products-and-platforms/products/gemini/gemini-personalization/))
3. **Search history:** the 2025 Personalization experiment connects Gemini to raw Google Search activity, rather than merely storing a chatbot-generated profile. Google planned/introduced broader Google-app context such as Photos and YouTube. ([Google announcement](https://blog.google/products-and-platforms/products/gemini/gemini-personalization/))

### Retrieval and controls

- Users select the Personalization model/mode and explicitly approve the Search-history connection. Web & App Activity must also be on. ([Google announcement](https://blog.google/products-and-platforms/products/gemini/gemini-personalization/))
- Gemini analyzes each prompt and consults Search history only when its reasoning model determines history would improve the answer. ([Google announcement](https://blog.google/products-and-platforms/products/gemini/gemini-personalization/))
- The response can identify whether saved info, past chats or Search history was used. Users can disconnect Search history and view/manage the underlying Search activity. ([Google announcement](https://blog.google/products-and-platforms/products/gemini/gemini-personalization/))
- Google’s support documentation centralizes controls under personal context/personalization; availability varies by age, language, location, model and account type, especially work/school accounts. ([Personalization help](https://support.google.com/gemini/answer/15637730?hl=en))

### Staleness/conflicts

**DOCUMENTED:** users can change/remove saved info and manage/delete underlying activity. Google documents conditional relevance at retrieval. ([Personalization help](https://support.google.com/gemini/answer/15637730?hl=en), [Google announcement](https://blog.google/products-and-platforms/products/gemini/gemini-personalization/))

**NOT DOCUMENTED:** Google does not explain how a contradiction between saved info, a recent chat and Search history is resolved, whether recency wins, or whether Search-derived preferences are persisted separately. Treat any such claim as inference.

### Privacy posture

Search personalization is affirmative-consent, source-transparent and revocable, making it the clearest opt-in among the four systems. However, it potentially exposes a much broader and more behaviorally sensitive raw dataset than fact/summarization memory. ([Google announcement](https://blog.google/products-and-platforms/products/gemini/gemini-personalization/), [Privacy Hub](https://support.google.com/gemini/answer/13594961?hl=en))

## 4. Microsoft Copilot memory and personalization

### Product model

**DOCUMENTED**

Microsoft announced in April 2025 that consumer Copilot would remember facts about users and use them to tailor future interactions, recommendations and proactive assistance. Users could tell Copilot to remember information and ask what it knew. ([Microsoft announcement](https://blogs.microsoft.com/blog/2025/04/04/copilot-your-ai-companion/))

**THIRD-PARTY REPORTED**

- Launch reporting described automatic accumulation of interests/preferences alongside explicit “remember” requests, plus user deletion and opt-out controls. ([The Verge](https://www.theverge.com/news/643225/microsoft-copilot-ai-features-memory-actions-vision), [GeekWire](https://www.geekwire.com/2025/microsoft-gives-copilot-its-own-memory-in-new-push-to-personalize-its-ai-assistant/))
- Microsoft later exposed a more directly editable profile under personalization/memory settings, according to hands-on reporting. ([ZDNET](https://www.zdnet.com/article/you-can-now-edit-microsoft-copilots-memories-about-you-heres-how/))

### Documented gaps

Microsoft’s public consumer material is less precise than OpenAI’s, Anthropic’s or Google’s documentation. It does **not** clearly specify:

- whether stored memory is atomic facts, a synthesized summary or both;
- extraction criteria and confidence thresholds;
- conflict/staleness precedence;
- inference-time retrieval mechanics;
- a project-scoped boundary comparable to Claude Projects or ChatGPT project-only memory;
- a dedicated incognito conversation mode with a documented no-read/no-write memory guarantee.

These should not be filled in from UI behavior without labeling the result as third-party observation.

### Consumer versus enterprise

Consumer memory is tied to the personal Copilot companion. Microsoft 365 Copilot’s organizational context is a different mechanism: it grounds responses through Microsoft Graph and honors existing identities, permissions, retention, audit and compliance controls. Microsoft states customer prompts, responses and Graph-grounded data are not used to train foundation models. ([Microsoft 365 privacy](https://learn.microsoft.com/en-us/copilot/microsoft-365/microsoft-365-copilot-privacy))

### Conflict and staleness

- **ChatGPT is most explicit:** new memory was designed to update stale facts and reconcile contradictions automatically. Exact precedence remains undisclosed. ([Memory FAQ](https://help.openai.com/en/articles/8590148-memory-faq))
- **Claude:** user can edit the one canonical summary and instruct focus/ignore; no documented automatic conflict algorithm. ([Anthropic announcement](https://claude.com/blog/memory))
- **Gemini:** retrieval is relevance-gated and underlying sources are manageable, but cross-source conflict precedence is undocumented. ([Google announcement](https://blog.google/products-and-platforms/products/gemini/gemini-personalization/))
- **Copilot:** editing/deletion exists, but conflict/staleness behavior is not adequately documented. ([ZDNET](https://www.zdnet.com/article/you-can-now-edit-microsoft-copilots-memories-about-you-heres-how/))

### Consent, privacy and deletion

- **Best explicit source consent:** Gemini asks before connecting Search history and shows the contributing source. ([Google announcement](https://blog.google/products-and-platforms/products/gemini/gemini-personalization/))
- **Best session-level escape hatches:** ChatGPT Temporary Chat and Claude Incognito both provide no personalization-memory read/write; ChatGPT documents a 30-day safety copy and limited safety-context exception. ([OpenAI Temporary Chat](https://help.openai.com/en/articles/8914046-temporary-chat-faq), [Claude memory](https://claude.com/blog/memory))
- **Deletion is source-sensitive:** ChatGPT explicitly warns that deleting the abstraction is insufficient if the source chat/file remains; this is an important general property of derived memory systems. ([Memory FAQ](https://help.openai.com/en/articles/8590148-memory-faq))
- **Training consent is separate from memory consent:** turning memory off does not inherently delete history, and model-training controls are separate. OpenAI and Microsoft separately document enterprise no-training defaults. ([OpenAI Projects](https://help.openai.com/en/articles/10169521-using-projects-in-chatgpt), [Microsoft 365 privacy](https://learn.microsoft.com/en-us/copilot/microsoft-365/microsoft-365-copilot-privacy))

### Opt-out/default posture

- **Claude:** documented opt-in; user enables it in Settings. ([Anthropic announcement](https://claude.com/blog/memory))
- **Gemini Search personalization:** documented opt-in; requires explicit connection and Web & App Activity. ([Google announcement](https://blog.google/products-and-platforms/products/gemini/gemini-personalization/))
- **ChatGPT:** controls are independently configurable, but rollout defaults have varied by plan, region and memory generation. The stable documented point is that users can enable saved memory only, saved memory plus chat history, or neither. ([Saved-memory reference](https://help.openai.com/en/articles/11146739-how-does-reference-saved-memories-work))
- **Copilot:** optional and disableable, but first-party material does not consistently specify a universal rollout default; do not claim one. ([Microsoft announcement](https://blogs.microsoft.com/blog/2025/04/04/copilot-your-ai-companion/), [The Verge](https://www.theverge.com/news/643225/microsoft-copilot-ai-features-memory-actions-vision))

### Enterprise/admin controls

- **OpenAI:** workspace memory/tool controls, RBAC for projects/sharing, compliance API, inherited retention/residency/audit controls and project isolation. ([Projects](https://help.openai.com/en/articles/10169521-using-projects-in-chatgpt))
- **Anthropic:** Enterprise admin can disable consumer memory; retention policy continues to apply. ([Anthropic announcement](https://claude.com/blog/memory))
- **Google:** personal-context feature availability is restricted for some work/school accounts; Google Workspace data governance should not be assumed equivalent to the consumer Search-history experiment. ([Personalization help](https://support.google.com/gemini/answer/15637730?hl=en))
- **Microsoft:** Microsoft 365 Copilot relies on tenant identity, Graph permissions and Purview/compliance controls; that is organizational grounding, not the consumer memory feature. ([Microsoft 365 privacy](https://learn.microsoft.com/en-us/copilot/microsoft-365/microsoft-365-copilot-privacy))

## Design lessons for remembering a professor’s teaching and assessment preferences

1. **Use a typed, inspectable profile—not only raw-chat retrieval.** Store explicit fields such as course, level, assessment type, permitted resources, question-style mix, Bloom-level targets, grading strictness, notation, accommodations and formatting. Raw sessions should remain provenance, not the canonical preference record. This combines ChatGPT’s durable-fact approach with Claude’s editable summary. ([OpenAI Memory FAQ](https://help.openai.com/en/articles/8590148-memory-faq), [Claude memory](https://claude.com/blog/memory))

2. **Separate professor-global from course/project-local memory.** Global: “prefers concise stems,” “uses partial credit,” “avoid trick questions.” Local: “CHEM-201 midterm is closed-book, 75 minutes, no spectroscopy.” Default to project/course isolation so one class cannot contaminate another, following Claude’s separate-project memory and ChatGPT project-only boundaries. ([Claude memory](https://claude.com/blog/memory), [ChatGPT Projects](https://help.openai.com/en/articles/10169521-using-projects-in-chatgpt))

3. **Require confirmation for high-impact assessment rules.** Automatically infer low-risk style preferences, but make exam duration, learning outcomes, allowed materials, grading weights and accommodations explicit/confirmed memories. Consumer products permit implicit writes, but assessment errors have higher consequences. ([OpenAI Memory FAQ](https://help.openai.com/en/articles/8590148-memory-faq))

4. **Attach provenance and timestamps to every memory.** Example: `prefers 40% application questions`, source `BIO-220 final planning, 2026-03-04`, confidence `explicit`. Surface “why this affected the exam,” analogous to OpenAI’s memory-source explanations and Gemini’s source transparency. ([OpenAI Memory FAQ](https://help.openai.com/en/articles/8590148-memory-faq), [Google personalization](https://blog.google/products-and-platforms/products/gemini/gemini-personalization/))

5. **Make conflict resolution visible.** Never silently merge “closed-book” and “open-note.” Show the conflict, favor the most recent explicit course-local statement over inferred/global memory, and ask for confirmation before generation. OpenAI’s stale-memory experience demonstrates why unattended contradictory facts degrade personalization. ([OpenAI Memory FAQ](https://help.openai.com/en/articles/8590148-memory-faq))

6. **Provide a pre-generation memory checkpoint.** Before authoring an exam, display the exact profile slice to be applied: course scope, assessment constraints and style preferences. Let the professor edit it inline or proceed without memory.

7. **Offer a true no-memory session.** A “Private exam session” should neither read nor write professor memory, while making retention behavior explicit, following Temporary Chat/Incognito rather than a vague history toggle. ([OpenAI Temporary Chat](https://help.openai.com/en/articles/8914046-temporary-chat-faq), [Claude memory](https://claude.com/blog/memory))

8. **Delete derived memory and its provenance together—or explain why not.** A professor deleting an assessment preference should be shown whether source transcripts remain capable of recreating it. OpenAI’s multi-source deletion requirement is the clearest warning against “delete card only” UX. ([OpenAI Memory FAQ](https://help.openai.com/en/articles/8590148-memory-faq))

9. **Retrieve just in time and within scope.** Load stable high-priority rules into every exam-authoring context; retrieve detailed examples/rubrics only when relevant. Anthropic’s developer memory tool explicitly documents this approach as a way to preserve context-window capacity. ([Claude memory tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool))

10. **Give institutional admins policy controls without taking authorship control from professors.** Admins should govern enablement, retention, residency, audit/export and sensitive-data categories; professors should control their profile and course boundaries. This mirrors OpenAI/Anthropic enterprise separation between workspace policy and personal/project memory. ([OpenAI Projects](https://help.openai.com/en/articles/10169521-using-projects-in-chatgpt), [Claude memory](https://claude.com/blog/memory))
