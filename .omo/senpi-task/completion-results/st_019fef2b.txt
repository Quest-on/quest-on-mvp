I read this as deep research on automatic long-term-memory write decisions and extractor prompts - I inspected primary-source repositories, product documentation, leaked prompt archives, and relevant papers, separating documented behavior from leaks and implementation recommendations.

# Automatic long-term-memory writes: what production systems actually do

## Evidence labels

- **DOCUMENTED**: vendor documentation, released source code, or published paper.
- **LEAKED / REVERSE-ENGINEERED**: prompt extracted from a hosted product; authenticity is not independently verified.
- **INFERRED**: synthesis or recommended design derived from cited evidence, not a vendor claim.

## Executive conclusion

Production-oriented memory systems generally do **not** use a single scalar “memory-worthiness” score. They use a pipeline:

1. Establish a trusted source scope: user messages, agent trajectory, or episodes.
2. Extract candidate facts under category and attribution rules.
3. Normalize candidates into standalone, temporally grounded statements.
4. Retrieve or provide nearby existing memories.
5. Classify each candidate as duplicate, enrichment, contradiction, new event, or deletion request.
6. Emit an operation such as `ADD`, `UPDATE`, `DELETE`, or `NONE`, or append a temporally versioned fact.
7. Apply deterministic deduplication and persistence checks outside the LLM.

This structure is directly visible in Mem0, LangMem, Letta, and Graphiti. [Mem0 prompts](https://github.com/mem0ai/mem0/blob/4debc58a83377b18be81ae1e5969a300736b2fac/mem0/configs/prompts.py) [LangMem manager](https://github.com/langchain-ai/langmem/blob/29cbe41e58528f92e9efa773c12e15c47be3808c/src/langmem/knowledge/extraction.py) [Letta sleeptime prompt](https://github.com/letta-ai/letta/blob/ff19ffeafeb54bd2a7dc5d4a552f10191732a235/letta/prompts/system_prompts/sleeptime_v2.py) [Graphiti edge resolution](https://github.com/getzep/graphiti/blob/401c59a65bdeb22a44136901ff30231e6998a7fe/graphiti_core/prompts/dedupe_edges.py)

The largest gap is **source trust**. Open-source extractors contain channel-separation and anti-hallucination rules, but few enforce a complete security boundary preventing instructions or claims inside uploaded documents, tool results, quoted text, or another user’s content from becoming durable memory. The feasibility of query-only memory poisoning has been demonstrated by MINJA, while AgentPoison showed effective poisoning with under 0.1% malicious records in its tested systems. [MINJA](https://arxiv.org/abs/2503.03704) [AgentPoison](https://arxiv.org/abs/2407.12784)

# 1. Public extraction and write-decision prompts

## 1.1 Mem0

### Classic fact extraction

**DOCUMENTED — source prompt, `mem0/configs/prompts.py`.**

Mem0’s classic `FACT_RETRIEVAL_PROMPT` begins:

```text
You are a Personal Information Organizer, specialized in accurately storing facts, user memories, and preferences. Your primary role is to extract relevant pieces of information from conversations and organize them into distinct, manageable facts.
```

Its positive categories are:

```text
1. Store Personal Preferences
2. Maintain Important Personal Details
3. Track Plans and Intentions
4. Remember Activity and Service Preferences
5. Monitor Health and Wellness Preferences
6. Store Professional Details
7. Miscellaneous Information Management
```

The final constraints include:

```text
- If you do not find anything relevant in the below conversation, you can return an empty list corresponding to the "facts" key.
- Create the facts based on the user and assistant messages only. Do not pick anything from the system messages.
...
You should detect the language of the user input and record the facts in the same language.
```

The expected output is effectively:

```json
{"facts": ["standalone fact", "..."]}
```

Source: [`mem0/configs/prompts.py`](https://github.com/mem0ai/mem0/blob/4debc58a83377b18be81ae1e5969a300736b2fac/mem0/configs/prompts.py#L15-L66).

Mem0 also has stricter user-only and assistant-only variants. The user variant repeats:

```text
# [IMPORTANT]: GENERATE FACTS SOLELY BASED ON THE USER'S MESSAGES. DO NOT INCLUDE INFORMATION FROM ASSISTANT OR SYSTEM MESSAGES.
# [IMPORTANT]: YOU WILL BE PENALIZED IF YOU INCLUDE INFORMATION FROM ASSISTANT OR SYSTEM MESSAGES.
```

This is a direct defense against assistant-output contamination, but not against quoted or injected content embedded inside a user message. [Source](https://github.com/mem0ai/mem0/blob/4debc58a83377b18be81ae1e5969a300736b2fac/mem0/configs/prompts.py#L69-L139)

### Classic `ADD / UPDATE / DELETE / NONE` prompt

**DOCUMENTED — source prompt, though no longer the active path in the inspected mainline pipeline.**

The real opening is:

```text
You are a smart memory manager which controls the memory of a system.
You can perform four operations: (1) add into the memory, (2) update the memory, (3) delete from the memory, and (4) no change.
```

Its decision rule is:

```text
Compare newly retrieved facts with the existing memory. For each new fact, decide whether to:
- ADD: Add it to the memory as a new element
- UPDATE: Update an existing memory element
- DELETE: Delete an existing memory element
- NONE: Make no change (if the fact is already present or irrelevant)
```

The key update logic is:

```text
If the retrieved fact contains information that conveys the same thing as the elements present in the memory, then you have to keep the fact which has the most information.
```

The contradiction logic is:

```text
If the retrieved facts contain information that contradicts the information present in the memory, then you have to delete it.
```

The output schema embedded in the prompt is:

```json
{
  "memory": [
    {
      "id": "<ID of the memory>",
      "text": "<Content of the memory>",
      "event": "<Operation to be performed>",
      "old_memory": "<Old memory content>"
    }
  ]
}
```

`event` must be `ADD`, `UPDATE`, `DELETE`, or `NONE`; `old_memory` is required for updates. Existing IDs must be retained for update/delete, while additions receive a new key. [Prompt](https://github.com/mem0ai/mem0/blob/4debc58a83377b18be81ae1e5969a300736b2fac/mem0/configs/prompts.py#L176-L461)

**Important implementation finding:** at the inspected commit, Mem0’s active OSS `add(..., infer=True)` path uses a newer **V3 additive-only pipeline**, not this classic mutation prompt. It makes one extraction call using `ADDITIVE_EXTRACTION_PROMPT`, asks for JSON, then exact-deduplicates extracted text by MD5 before insertion. [Active pipeline](https://github.com/mem0ai/mem0/blob/4debc58a83377b18be81ae1e5969a300736b2fac/mem0/memory/main.py#L917-L1074)

### Current V3 additive extractor

**DOCUMENTED.**

The V3 role is explicitly:

```text
You are a Memory Extractor — a precise, evidence-bound processor responsible for extracting rich, contextual memories from conversations. Your sole operation is ADD
```

Its deduplication boundary is:

```text
Use these ONLY for deduplication and linking — do NOT extract new memories from Existing Memories. Your extractions must come exclusively from New Messages.
```

It also distinguishes duplicates from new events involving an already-known entity:

```text
Only skip extraction when the specific fact or event itself is already captured — not merely because the entity appears in an existing memory.
```

Its negative rules include:

```text
- No Fabrication
- No Implicit Attribute Inference
- Correct Attribution
- No Echo Extraction
- No Within-Response Duplication
- No Meta-Extraction
- No Detail Contamination from Context
```

Its current output fields are:

```text
- id: Sequential integers as strings starting at "0".
- text: A contextually rich, self-contained factual statement (15-80 words).
- attributed_to: "user" or "assistant".
- linked_memory_ids: IDs of related Existing Memories.
```

[Full V3 prompt](https://github.com/mem0ai/mem0/blob/4debc58a83377b18be81ae1e5969a300736b2fac/mem0/configs/prompts.py#L464-L965) [Output fields](https://github.com/mem0ai/mem0/blob/4debc58a83377b18be81ae1e5969a300736b2fac/mem0/configs/prompts.py#L930-L954)

A notable risk is that the V3 prompt affirmatively instructs extraction from “documents, case studies, articles, data, specifications, stat blocks, code, or any structured information” shared by the user. Without provenance controls, that converts untrusted document content into memory candidates. [Source](https://github.com/mem0ai/mem0/blob/4debc58a83377b18be81ae1e5969a300736b2fac/mem0/configs/prompts.py#L552-L561)

## 1.2 LangMem

### Background memory-manager prompt

**DOCUMENTED — `src/langmem/knowledge/extraction.py`.**

The real `_MEMORY_INSTRUCTIONS` opens:

```text
You are a long-term memory manager maintaining a core store of semantic, procedural, and episodic memory. These memories power a life-long learning agent's core predictive model.

What should the agent learn from this interaction about the user, itself, or how it should act?
```

Its extraction and update instructions are unusually explicit:

```text
1. Extract & Contextualize
- Identify essential facts, relationships, preferences, reasoning procedures, and context
- Caveat uncertain or suppositional information with confidence levels (p(x)) and reasoning

2. Compare & Update
- Attend to novel information that deviates from existing memories and expectations.
- Consolidate and compress redundant memories...
- Remove incorrect or redundant memories while maintaining internal consistency

3. Synthesize & Reason
- What can you conclude ... using deduction, induction, and abduction?
```

Its salience sentence is:

```text
Prioritize retention of surprising (pattern deviation) and persistent (frequently reinforced) information, ensuring nothing worth remembering is forgotten and nothing false is remembered.
```

[Source](https://github.com/langchain-ai/langmem/blob/29cbe41e58528f92e9efa773c12e15c47be3808c/src/langmem/knowledge/extraction.py#L184-L214)

The runtime adds:

```text
Enrich, prune, and organize memories based on any new information.
If an existing memory is incorrect or outdated, update it based on the new information.
All operations must be done in single parallel multi-tool call.
Avoid duplicate extractions.
```

[Source](https://github.com/langchain-ai/langmem/blob/29cbe41e58528f92e9efa773c12e15c47be3808c/src/langmem/knowledge/extraction.py#L519-L540)

### Tool schemas and operation controls

**DOCUMENTED.**

The default memory tool schema is a Pydantic model:

```python
class Memory(BaseModel):
    """Call this tool once for each new memory you want to record."""
    content: str = Field(
        description="The memory as a well-written, standalone episode/fact/note/preference/etc."
    )
```

[Source](https://github.com/langchain-ai/langmem/blob/29cbe41e58528f92e9efa773c12e15c47be3808c/src/langmem/knowledge/extraction.py#L72-L80)

LangMem delegates insert/update/delete tool construction to Trustcall and exposes independent controls:

```text
enable_inserts=True
enable_updates=True
enable_deletes=False
```

Deletion is deliberately disabled by default, reducing destructive mistakes. Existing document IDs are carried through update/removal responses, and a `Done` tool terminates multi-step consolidation. [Source](https://github.com/langchain-ai/langmem/blob/29cbe41e58528f92e9efa773c12e15c47be3808c/src/langmem/knowledge/extraction.py#L217-L334)

Its hot-path `manage_memory` tool has the effective schema:

```python
def manage_memory(
    content: str | None = None,
    id: str | None = None,
    action: Literal["create", "update", "delete"] = "create",
) -> str
```

The default tool-description decision boundary is:

```text
Proactively call this tool when you:

1. Identify a new USER preference.
2. Receive an explicit USER request to remember something or otherwise alter your behavior.
3. Are working and want to record important context.
4. Identify that an existing MEMORY is incorrect or outdated.
```

[Source](https://github.com/langchain-ai/langmem/blob/29cbe41e58528f92e9efa773c12e15c47be3808c/src/langmem/knowledge/tools.py#L20-L74)

## 1.3 Letta

### Sleeptime memory prompt

**DOCUMENTED — `letta/prompts/system_prompts/sleeptime_v2.py`.**

Letta runs a dedicated background memory agent whose prompt says:

```text
You run in the background, organizing and maintaining the memories of an agent assistant who chats with the user.
```

Its write goal is:

```text
You goal is to make sure the memory blocks are comprehensive, readable, and up to date.
```

It requires absolute temporal grounding:

```text
do not write "today" or "recently", instead write specific dates and times, because "today" and "recently" are relative, and the memory is persisted indefinitely
```

Its negative/no-op rule is:

```text
If there are no meaningful updates to make to the memory, you call the finish tool directly.
Not every observation warrants a memory edit, be selective in your memory editing, but also aim to have high recall.
```

[Full prompt](https://github.com/letta-ai/letta/blob/ff19ffeafeb54bd2a7dc5d4a552f10191732a235/letta/prompts/system_prompts/sleeptime_v2.py)

The background wrapper reiterates:

```text
Review the conversation and use your memory tools to update any relevant memory blocks with information worth preserving.
Check your memory_persona block for any additional instructions or policies.
```

It clearly labels assistant messages as coming from the foreground agent and user messages as coming from the foreground user. [Source](https://github.com/letta-ai/letta/blob/ff19ffeafeb54bd2a7dc5d4a552f10191732a235/letta/groups/sleeptime_multi_agent_v4.py#L205-L250)

### Memory-editing tool definitions

**DOCUMENTED.**

Letta exposes precise edits rather than an abstract `UPDATE`:

```python
memory_replace(label: str, old_string: str, new_string: str)
memory_insert(label: str, new_string: str, insert_line: int = -1)
memory_rethink(label: str, new_memory: str)
memory_finish_edits()
```

`memory_replace` requires `old_string` to occur exactly once; zero or multiple matches fail. This is an optimistic-concurrency-like guard against editing the wrong passage. [Source](https://github.com/letta-ai/letta/blob/ff19ffeafeb54bd2a7dc5d4a552f10191732a235/letta/functions/function_sets/base.py#L311-L388)

`memory_rethink` is reserved for “large sweeping changes,” while narrow changes should use insertion or replacement. [Source](https://github.com/letta-ai/letta/blob/ff19ffeafeb54bd2a7dc5d4a552f10191732a235/letta/functions/function_sets/base.py#L489-L518)

Archival-memory insertion is described as:

```text
Store self-contained facts or summaries, not conversational fragments
Use for: meeting notes, project updates, conversation summaries, events, reports
Information stored here persists indefinitely
```

[Source](https://github.com/letta-ai/letta/blob/ff19ffeafeb54bd2a7dc5d4a552f10191732a235/letta/functions/function_sets/base.py#L164-L204)

## 1.4 Graphiti

Graphiti’s memory write decision is graph-oriented: extract entities and relationship facts, resolve duplicates, then invalidate temporally conflicting edges instead of rewriting a single user-profile string. [Zep paper](https://arxiv.org/abs/2501.13956) [Graphiti source](https://github.com/getzep/graphiti/tree/401c59a65bdeb22a44136901ff30231e6998a7fe/graphiti_core/prompts)

### Combined extraction prompt and schema

**DOCUMENTED.**

The system prompt says:

```text
You are an expert knowledge graph extraction specialist for an AI agent memory system.
...
The original conversation will NOT be available at retrieval time — only the entities and facts you extract will survive.
```

Its fact rule is permissive:

```text
Extract liberally — when in doubt, extract the fact. Preferences, opinions, reactions, advice, plans, states, and experiences are all valuable.
```

But its entity rules aggressively reject prompt scaffolding, generic nouns, tutorial examples, multiple-choice labels, dates as entities, and imperative advice headings. [Source](https://github.com/getzep/graphiti/blob/401c59a65bdeb22a44136901ff30231e6998a7fe/graphiti_core/prompts/extract_nodes_and_edges.py#L91-L307)

The response schema is:

```python
class CombinedEntity:
    name: str
    entity_type_id: int

class CombinedFact:
    source_entity_name: str
    target_entity_name: str
    relation_type: str
    fact: str
    episode_indices: list[int]

class CombinedExtraction:
    extracted_entities: list[CombinedEntity]
    edges: list[CombinedFact]
```

[Source](https://github.com/getzep/graphiti/blob/401c59a65bdeb22a44136901ff30231e6998a7fe/graphiti_core/prompts/extract_nodes_and_edges.py#L26-L69)

### Edge extraction and conflict schema

**DOCUMENTED.**

Graphiti extracts only facts “clearly stated or unambiguously implied,” requires source and target names from the supplied entity list, preserves concrete details, and returns `valid_at` / `invalid_at` timestamps. [Prompt and schema](https://github.com/getzep/graphiti/blob/401c59a65bdeb22a44136901ff30231e6998a7fe/graphiti_core/prompts/extract_edges.py#L25-L179)

Its conflict resolver returns:

```python
class EdgeDuplicate(BaseModel):
    duplicate_facts: list[int]
    contradicted_facts: list[int]
```

The real decision examples are:

```text
"Alice joined Acme Corp in 2020"
vs same fact
→ duplicate_facts=[0], contradicted_facts=[]

"Alice works at Acme Corp as a software engineer"
vs "Alice works at Acme Corp as a senior engineer"
→ duplicate_facts=[], contradicted_facts=[1]

"Bob ran 5 miles on Tuesday"
vs "Bob ran 3 miles on Wednesday"
→ duplicate_facts=[], contradicted_facts=[]
```

[Source](https://github.com/getzep/graphiti/blob/401c59a65bdeb22a44136901ff30231e6998a7fe/graphiti_core/prompts/dedupe_edges.py#L24-L104)

The associated Zep design invalidates an old edge only when a new edge is contradictory and temporally overlapping, setting the old edge’s invalid time to the new edge’s valid time. This avoids treating separate dated events as contradictions. [Zep paper, §2.2.3](https://arxiv.org/abs/2501.13956)

# 3. Salience and memory-worthiness

## What existing systems operationalize

### Durability

- The leaked ChatGPT prompt rejects short-term interests, current projects, desires, and wishes. [Unverified leak](https://github.com/jujumilk3/leaked-system-prompts/blob/main/openai-chatgpt4.1_20250515.md)
- The leaked Copilot prompt asks whether the fact will affect responses in future conversations and rejects current-conversation-only context. [Unverified leak](https://github.com/jujumilk3/leaked-system-prompts/blob/main/microsoft-copilot_20260328.md#memory_durable_fact)
- Letta requires absolute dates because memory persists indefinitely. [Letta prompt](https://github.com/letta-ai/letta/blob/ff19ffeafeb54bd2a7dc5d4a552f10191732a235/letta/prompts/system_prompts/sleeptime_v2.py)

### Generality and actionability

- LangMem asks what the agent should learn “about the user, itself, or how it should act” and seeks principles about optimal responses. [LangMem](https://github.com/langchain-ai/langmem/blob/29cbe41e58528f92e9efa773c12e15c47be3808c/src/langmem/knowledge/extraction.py#L184-L214)
- LangMem’s hot-path tool is triggered by preferences, explicit behavior-change requests, important working context, or outdated memory. [LangMem tool](https://github.com/langchain-ai/langmem/blob/29cbe41e58528f92e9efa773c12e15c47be3808c/src/langmem/knowledge/tools.py#L20-L74)

### Explicitness and confidence

- Graphiti’s edge extractor accepts facts clearly stated or unambiguously implied. [Graphiti](https://github.com/getzep/graphiti/blob/401c59a65bdeb22a44136901ff30231e6998a7fe/graphiti_core/prompts/extract_edges.py#L109-L179)
- Mem0 V3 forbids implicit inference of age, gender, ethnicity, and similar attributes and requires traceability to input. [Mem0 V3](https://github.com/mem0ai/mem0/blob/4debc58a83377b18be81ae1e5969a300736b2fac/mem0/configs/prompts.py#L684-L706)
- LangMem instead permits deduction, induction, and abduction, but asks for probabilistic confidence and justification. [LangMem](https://github.com/langchain-ai/langmem/blob/29cbe41e58528f92e9efa773c12e15c47be3808c/src/langmem/knowledge/extraction.py#L184-L214)

### Importance and repetition

**DOCUMENTED paper result:** Generative Agents asks the LLM:

```text
On the scale of 1 to 10, where 1 is purely mundane
(e.g., brushing teeth, making bed) and 10 is extremely poignant
(e.g., a break up, college acceptance), rate the likely poignancy
of the following piece of memory.
```

It stores this score when the observation is created and triggers higher-level reflection when the cumulative importance of recent events exceeds 150. This is a consolidation threshold, not a raw-write threshold. [Generative Agents, §4.1–4.2](https://arxiv.org/abs/2304.03442)

**DOCUMENTED paper result:** MemoryBank initializes memory strength `S=1`, increments it, and resets decay time when a memory is recalled; repetition therefore increases persistence rather than determining whether the first observation is written. [MemoryBank, §2.3](https://arxiv.org/abs/2305.10250)

**DOCUMENTED:** LangMem describes persistence as “frequently reinforced” information, but publishes no fixed `N`-observation threshold. [LangMem](https://github.com/langchain-ai/langmem/blob/29cbe41e58528f92e9efa773c12e15c47be3808c/src/langmem/knowledge/extraction.py#L184-L214)

### Practical conclusion

**INFERRED:** fixed repetition thresholds are useful primarily for **inferred traits**, not explicit facts. Requiring the user to state their name or accessibility need multiple times destroys recall; accepting a personality characterization after one ambiguous interaction creates stereotypes. This distinction follows from Mem0’s no-inference rule, LangMem’s confidence treatment, and MemoryBank’s use of repetition to strengthen rather than initially admit memories. [Mem0](https://github.com/mem0ai/mem0/blob/4debc58a83377b18be81ae1e5969a300736b2fac/mem0/configs/prompts.py) [LangMem](https://github.com/langchain-ai/langmem/blob/29cbe41e58528f92e9efa773c12e15c47be3808c/src/langmem/knowledge/extraction.py) [MemoryBank](https://arxiv.org/abs/2305.10250)

# 4. The update decision and contradiction handling

## Existing patterns

### Mem0 classic: destructive four-way decision

**DOCUMENTED:** exact/semantic duplicate → `NONE`; richer equivalent → `UPDATE`; new information → `ADD`; contradiction → `DELETE`. Updates retain IDs. [Mem0 update prompt](https://github.com/mem0ai/mem0/blob/4debc58a83377b18be81ae1e5969a300736b2fac/mem0/configs/prompts.py#L176-L461)

Weakness: the contradiction example deletes “Loves cheese pizza” after seeing “Dislikes cheese pizza,” but does not clearly require adding the new negative preference. A literal implementation can erase both old and new state. [Same source](https://github.com/mem0ai/mem0/blob/4debc58a83377b18be81ae1e5969a300736b2fac/mem0/configs/prompts.py#L326-L376)

### LangMem: patch existing typed documents

**DOCUMENTED:** existing document IDs are supplied to the extractor, which can insert, patch, or remove typed documents; deletion is disabled by default. Multi-step mode returns tool feedback and asks the manager to continue consolidating until `Done`. [LangMem](https://github.com/langchain-ai/langmem/blob/29cbe41e58528f92e9efa773c12e15c47be3808c/src/langmem/knowledge/extraction.py#L217-L444)

### Letta: exact text edits

**DOCUMENTED:** replacement fails unless the old string appears exactly once, limiting accidental updates when the memory changed between reading and writing. [Letta](https://github.com/letta-ai/letta/blob/ff19ffeafeb54bd2a7dc5d4a552f10191732a235/letta/functions/function_sets/base.py#L311-L388)

### Graphiti: temporal append and invalidation

**DOCUMENTED:** new facts are appended with validity intervals; duplicate and contradiction are separate labels; only temporally overlapping contradictions invalidate prior facts. [Graphiti resolver](https://github.com/getzep/graphiti/blob/401c59a65bdeb22a44136901ff30231e6998a7fe/graphiti_core/prompts/dedupe_edges.py) [Zep paper](https://arxiv.org/abs/2501.13956)

## Preventing contradiction ping-pong

**INFERRED implementation policy:**

1. Never let weak inference overwrite a direct statement.
2. Treat dated events as separate episodes unless they claim the same current-state slot.
3. Keep observation time, valid time, source message ID, source actor, and explicit/inferred status.
4. On conflict, prefer explicit correction over older explicit statement; otherwise retain both as disputed or pending.
5. Invalidate the previous current-state record only when the replacement is successfully committed.
6. Record the transition in one transaction: close old version and open new version.
7. Do not turn negation into delete-only; preserve the new negative fact.
8. Require a materially different normalized value before updating.
9. Add hysteresis for inferred traits: for example, two independent confirmations to create and stronger evidence to reverse.
10. Never use retrieval rank or embedding similarity as evidence that two facts contradict.

These recommendations combine Graphiti’s temporal invalidation, Letta’s exact-match edits, LangMem’s confidence language, and the failure mode in Mem0’s delete example. [Graphiti](https://github.com/getzep/graphiti/blob/401c59a65bdeb22a44136901ff30231e6998a7fe/graphiti_core/prompts/dedupe_edges.py) [Letta](https://github.com/letta-ai/letta/blob/ff19ffeafeb54bd2a7dc5d4a552f10191732a235/letta/functions/function_sets/base.py) [LangMem](https://github.com/langchain-ai/langmem/blob/29cbe41e58528f92e9efa773c12e15c47be3808c/src/langmem/knowledge/extraction.py) [Mem0](https://github.com/mem0ai/mem0/blob/4debc58a83377b18be81ae1e5969a300736b2fac/mem0/configs/prompts.py)

# 5. Negative and safety rules

## Sensitive categories

**DOCUMENTED product guidance:** OpenAI says sensitive information such as health details should not be proactively remembered unless explicitly requested. [OpenAI Memory FAQ](https://help.openai.com/en/articles/8590148-memory-faq)

**LEAKED / unverified:** ChatGPT’s 2025 denylist covers race, ethnicity, religion, sexual orientation, politics, sex life, criminal history, medical diagnoses/prescriptions, and union membership. [Leak](https://github.com/jujumilk3/leaked-system-prompts/blob/main/openai-chatgpt4.1_20250515.md)

**DOCUMENTED:** Mem0’s own documentation warns against storing secrets or unredacted PII because memory is retrievable by design. [Mem0 memory types](https://github.com/mem0ai/mem0/blob/4debc58a83377b18be81ae1e5969a300736b2fac/docs/core-concepts/memory-types.mdx#L90-L94)

## Third-party personal data

Microsoft’s public example says Copilot may remember a nephew’s birthday and interests, demonstrating that at least one product treats some third-party relationship data as personalizable memory. [Microsoft](https://blogs.microsoft.com/blog/2025/04/04/your-ai-companion/)

**INFERRED recommendation:** third-party data should require stricter necessity and sensitivity checks than first-party preferences. A durable statement such as “user has a daughter named Sara” may be useful, but medical, financial, contact, precise-location, credential, or intimate information about Sara should not be stored merely because the user mentioned it. This recommendation is stricter than Microsoft’s public example and follows the retrievability and poisoning risks of persistent memory. [Microsoft](https://blogs.microsoft.com/blog/2025/04/04/your-ai-companion/) [Mem0 warning](https://github.com/mem0ai/mem0/blob/4debc58a83377b18be81ae1e5969a300736b2fac/docs/core-concepts/memory-types.mdx#L90-L94) [MINJA](https://arxiv.org/abs/2503.03704)

## Transient state

- ChatGPT’s leaked prompt rejects short-term interests, projects, desires, and wishes. [Unverified leak](https://github.com/jujumilk3/leaked-system-prompts/blob/main/openai-chatgpt4.1_20250515.md)
- Letta says not every observation warrants an edit. [Letta](https://github.com/letta-ai/letta/blob/ff19ffeafeb54bd2a7dc5d4a552f10191732a235/letta/prompts/system_prompts/sleeptime_v2.py)
- Graphiti is intentionally more episodic and extracts plans, states, reactions, and commitments, but attaches episode and temporal information rather than forcing them into an eternal profile. [Graphiti](https://github.com/getzep/graphiti/blob/401c59a65bdeb22a44136901ff30231e6998a7fe/graphiti_core/prompts/extract_nodes_and_edges.py)

## Memory injection

**DOCUMENTED incident research:** AgentPoison demonstrated poisoning of long-term memory or RAG knowledge bases with a poisoning ratio below 0.1%, reporting 82% retrieval success and 63% end-to-end attack success in its main comparison. [AgentPoison](https://arxiv.org/abs/2407.12784)

**DOCUMENTED incident research:** MINJA removes the need for direct memory-database access: an attacker can inject malicious records through normal query interaction and output observation. [MINJA](https://arxiv.org/abs/2503.03704)

Channel separation alone is insufficient. Mem0 user-only extraction prevents assistant echoes from becoming memory, but a malicious document pasted inside the user message still occupies the trusted `user` channel; Mem0 V3 explicitly asks to extract facts from shared documents. [Mem0 user-only prompt](https://github.com/mem0ai/mem0/blob/4debc58a83377b18be81ae1e5969a300736b2fac/mem0/configs/prompts.py#L69-L139) [Mem0 shared-content rule](https://github.com/mem0ai/mem0/blob/4debc58a83377b18be81ae1e5969a300736b2fac/mem0/configs/prompts.py#L552-L561)

**INFERRED minimum defense:**

- Assign every span a provenance type: direct user assertion, user quotation, attachment, tool output, web result, assistant output, or other participant.
- Permit automatic personal-memory writes only from direct assertions by the memory owner.
- Treat instructions inside attachments, retrieved pages, and quoted text as data, never extractor policy.
- Do not share memory banks across users or tenants.
- Bind writes to authenticated tenant/user IDs server-side.
- Store source message IDs and immutable evidence spans.
- Rate-limit writes and alert on bursts, repeated near-duplicates, or sudden behavioral-rule creation.
- Separate factual user memory from executable procedures, policies, demonstrations, and agent instructions.
- Require explicit confirmation for sensitive information and durable behavioral rules originating in external content.
- Apply deterministic category filters after extraction; prompts are not security controls.

These controls address the query-only and direct-database poisoning threat models demonstrated by MINJA and AgentPoison. [MINJA](https://arxiv.org/abs/2503.03704) [AgentPoison](https://arxiv.org/abs/2407.12784)

# 6. Operational shape

## When extraction runs

### Sync / hot path

**DOCUMENTED:** LangMem calls active formation “hot path” memory; it provides immediate updates but adds perceptible latency and complicates the agent’s tool choices. [LangMem conceptual guide](https://github.com/langchain-ai/langmem/blob/29cbe41e58528f92e9efa773c12e15c47be3808c/docs/docs/concepts/conceptual_guide.md#writing-memories)

### Background / end of activity

**DOCUMENTED:** LangMem background formation reflects after a conversation or quiet period without slowing immediate interaction. Its `ReflectionExecutor` cancels pending work when a new message arrives and reschedules using the enlarged context. [Conceptual guide](https://github.com/langchain-ai/langmem/blob/29cbe41e58528f92e9efa773c12e15c47be3808c/docs/docs/concepts/conceptual_guide.md#writing-memories) [Delayed processing](https://github.com/langchain-ai/langmem/blob/29cbe41e58528f92e9efa773c12e15c47be3808c/docs/docs/guides/delayed_processing.md)

**DOCUMENTED:** Letta sleeptime agents run asynchronously after foreground responses and can be configured to run every `N` turns. They track a `last_processed_message_id` to select messages since the prior background pass. [Letta](https://github.com/letta-ai/letta/blob/ff19ffeafeb54bd2a7dc5d4a552f10191732a235/letta/groups/sleeptime_multi_agent_v4.py#L132-L264)

### Periodic consolidation

**DOCUMENTED:** Generative Agents triggers reflection once accumulated importance exceeds 150, which produced roughly two or three reflections per simulated day. [Generative Agents](https://arxiv.org/abs/2304.03442)

## Idempotency

**DOCUMENTED:** current Mem0 computes an MD5 hash of normalized extracted text and skips exact hash matches against existing results and the current extraction batch. This is exact textual idempotency, not semantic idempotency. [Mem0](https://github.com/mem0ai/mem0/blob/4debc58a83377b18be81ae1e5969a300736b2fac/mem0/memory/main.py#L1000-L1032)

**DOCUMENTED:** Letta tracks the last processed message ID, but that cursor alone does not prove exactly-once persistence if a worker crashes after writes and before successful completion. [Letta](https://github.com/letta-ai/letta/blob/ff19ffeafeb54bd2a7dc5d4a552f10191732a235/letta/groups/sleeptime_multi_agent_v4.py#L132-L264)

**INFERRED recommendation:** use an idempotency key such as:

```text
tenant_id + user_id + source_message_range + extractor_version + candidate_slot
```

and enforce a unique database constraint. Content hashes should be secondary deduplication aids because harmless rephrasing changes the hash, while identical text can represent distinct dated events. This follows from Mem0’s exact-hash mechanism and Graphiti’s episode-aware duplicate examples. [Mem0](https://github.com/mem0ai/mem0/blob/4debc58a83377b18be81ae1e5969a300736b2fac/mem0/memory/main.py#L1000-L1032) [Graphiti](https://github.com/getzep/graphiti/blob/401c59a65bdeb22a44136901ff30231e6998a7fe/graphiti_core/prompts/dedupe_edges.py)

## Prompt versioning and re-extraction

No inspected system demonstrates a complete public scheme that stores a stable extractor-prompt version on every memory and automatically re-extracts source conversations after prompt changes. Graphiti organizes prompt implementations behind a `prompt_library`, but its `PromptVersion` is a callable protocol rather than persisted provenance metadata. [Graphiti prompt library](https://github.com/getzep/graphiti/blob/401c59a65bdeb22a44136901ff30231e6998a7fe/graphiti_core/prompts/lib.py) [Prompt models](https://github.com/getzep/graphiti/blob/401c59a65bdeb22a44136901ff30231e6998a7fe/graphiti_core/prompts/models.py)

**INFERRED recommendation:** persist model ID, prompt hash/version, schema version, extractor configuration, source IDs, observation date, and extraction timestamp. Re-extraction should create a shadow candidate set and diff it against production memory; it should not mutate live memory until evaluated. This is necessary because prompt changes can alter both what is extracted and whether prior facts are treated as duplicates or contradictions. [LongMemEval](https://arxiv.org/abs/2410.10813) [Graphiti prompts](https://github.com/getzep/graphiti/tree/401c59a65bdeb22a44136901ff30231e6998a7fe/graphiti_core/prompts)

## Cost per session

No cited vendor publishes a reliable universal extractor cost per session. Cost depends on transcript size, retrieved comparison memories, model, retries, number of reflection steps, embeddings, and whether conflict resolution is a separate call. LangMem explicitly identifies redundant per-message processing and unnecessary token consumption as reasons to debounce. [LangMem delayed processing](https://github.com/langchain-ai/langmem/blob/29cbe41e58528f92e9efa773c12e15c47be3808c/docs/docs/guides/delayed_processing.md)

At the inspected commit, Mem0’s main inference path makes a single JSON extraction call after retrieving up to ten similar memories, then batches embeddings and persistence. This provides an auditable call shape but not a vendor-wide monetary cost. [Mem0 active pipeline](https://github.com/mem0ai/mem0/blob/4debc58a83377b18be81ae1e5969a300736b2fac/mem0/memory/main.py#L917-L1074)

## Observability

Letta includes optional LLM trace storage and a ClickHouse provider-trace backend intended for cost analytics, but tracing alone does not measure extraction quality. [Letta trace backend](https://github.com/letta-ai/letta/blob/ff19ffeafeb54bd2a7dc5d4a552f10191732a235/letta/services/provider_trace_backends/clickhouse.py)

**INFERRED minimum dashboard:**

- candidate and accepted memories per conversation;
- empty-extraction rate by conversation class;
- create/update/delete/no-op distribution;
- duplicate rate before and after deterministic dedup;
- sensitive-category block rate;
- provenance distribution;
- inferred-vs-explicit ratio;
- contradiction and reversal rate;
- memories later edited or deleted by users;
- extractor latency, input/output tokens, retries, parse failures, and cost;
- shadow-evaluation precision/recall by prompt/model version.

This extends observable traces into quality and safety indicators, which are necessary because extraction regressions can manifest as both missed memories and excessive writes. [LongMemEval](https://arxiv.org/abs/2410.10813) [LangMem delayed processing](https://github.com/langchain-ai/langmem/blob/29cbe41e58528f92e9efa773c12e15c47be3808c/docs/docs/guides/delayed_processing.md)

## Offline evaluation

**DOCUMENTED:** LongMemEval evaluates five capabilities: information extraction, multi-session reasoning, temporal reasoning, knowledge updates, and abstention. It provides a public user-fact extraction prompt that requests standalone JSON facts and an empty list when nothing qualifies. [LongMemEval](https://arxiv.org/abs/2410.10813)

Its published extractor prompt includes:

```text
Extract all the personal information, life events, experience, and preferences related to the user.
...
State each piece of information in a simple sentence.
...
If there is no specific events, personal information, or preference mentioned, just generate an empty list.
```

[LongMemEval appendix](https://arxiv.org/abs/2410.10813)

**INFERRED extractor-specific evaluation should score:**

1. Candidate precision and recall at fact level.
2. Correct abstention on empty/transient/untrusted inputs.
3. Attribution accuracy.
4. Sensitive-category violation rate.
5. Temporal-normalization accuracy.
6. Duplicate classification.
7. Conflict operation accuracy.
8. Preservation of proper nouns, quantities, negation, and modality.
9. Idempotency under paraphrase and replay.
10. Robustness to assistant echoes, quotations, documents, prompt injections, and cross-user content.
11. Downstream utility: whether accepted memory changes a future answer appropriately.
12. User correction/deletion rate in production.

LongMemEval is useful for downstream memory capability, while a separate labeled extractor suite is required to isolate write-decision quality. [LongMemEval](https://arxiv.org/abs/2410.10813)

# 7. Implementable write-decision rubric

The following is **INFERRED**, synthesized from the cited systems and papers.

## Stage A: hard eligibility

Reject automatically if any condition is true:

1. Source is system text, tool output, retrieved web content, uploaded document, quoted dialogue, assistant speculation, or another user’s content, unless an application-specific trusted-ingestion flow explicitly permits it.
2. Candidate contains secrets, authentication material, financial account data, or prohibited sensitive categories.
3. Candidate concerns sensitive third-party data.
4. It is conversational filler, a request without a personal assertion, generic world knowledge, or merely describes the current task.
5. It is transient with no explicit future relevance.
6. It is an inference of a protected or sensitive attribute.
7. The evidence cannot be pointed to as an exact source span.

This combines Mem0’s attribution/integrity rules, the ChatGPT leaked denylist, and memory-poisoning evidence. [Mem0](https://github.com/mem0ai/mem0/blob/4debc58a83377b18be81ae1e5969a300736b2fac/mem0/configs/prompts.py) [ChatGPT leak](https://github.com/jujumilk3/leaked-system-prompts/blob/main/openai-chatgpt4.1_20250515.md) [MINJA](https://arxiv.org/abs/2503.03704)

## Stage B: score qualifying candidates

Score each dimension `0–2`:

| Dimension | 0 | 1 | 2 |
|---|---|---|---|
| Durability | hours/days | dated event or medium-term plan | likely stable for months |
| Future actionability | no effect | occasional context | materially changes future response |
| Generality | only this turn/task | one project/domain | broad user behavior/profile |
| Explicitness | model inference | unambiguous implication | direct statement/request |
| Specificity | vague | partially grounded | standalone names/dates/details |
| Reinforcement | contradicted/one weak cue | one direct observation | explicit save request or repeated confirmation |
| Sensitivity risk | prohibited | requires confirmation | ordinary preference/fact |
| Source trust | untrusted | trusted ingestion | direct authenticated user assertion |

The durability/actionability tests mirror leaked Copilot and ChatGPT guidance; explicitness and specificity mirror Graphiti and Mem0; reinforcement follows LangMem and MemoryBank. [Copilot leak](https://github.com/jujumilk3/leaked-system-prompts/blob/main/microsoft-copilot_20260328.md#memory_durable_fact) [ChatGPT leak](https://github.com/jujumilk3/leaked-system-prompts/blob/main/openai-chatgpt4.1_20250515.md) [Graphiti](https://github.com/getzep/graphiti/blob/401c59a65bdeb22a44136901ff30231e6998a7fe/graphiti_core/prompts/extract_edges.py) [MemoryBank](https://arxiv.org/abs/2305.10250)

## Stage C: threshold

- Explicit “remember this”: write if allowed and non-sensitive.
- Direct stable fact or preference: write at score ≥11/16.
- Dated episodic event: write at ≥10 only into episodic memory with validity time.
- Inferred non-sensitive trait: require score ≥13 plus at least two independent observations.
- Behavioral rule affecting future agent action: require direct instruction or explicit confirmation.
- Sensitive-but-allowable category: require explicit user request and a dedicated consent path.
- Otherwise: no-op or retain as short-term context.

## Stage D: operation against existing memory

1. Same proposition, same value, same temporal scope → `NOOP`.
2. Same proposition, richer compatible detail → `UPDATE` or merge.
3. Same entity but distinct event/time → `ADD`.
4. Explicit correction of a current-state fact → atomic `UPDATE`, preserving history.
5. New contradictory current-state fact with reliable time → invalidate old version and `ADD` new version.
6. Weak or inferred contradiction → do not mutate; accumulate evidence or ask.
7. Explicit forget/delete request → `DELETE`, with identity and scope validation.
8. Prohibited content discovered in existing memory → policy deletion, separately audited.

This combines Mem0’s four-way classification with Graphiti’s temporal distinction and Letta’s precise edits. [Mem0](https://github.com/mem0ai/mem0/blob/4debc58a83377b18be81ae1e5969a300736b2fac/mem0/configs/prompts.py) [Graphiti](https://github.com/getzep/graphiti/blob/401c59a65bdeb22a44136901ff30231e6998a7fe/graphiti_core/prompts/dedupe_edges.py) [Letta](https://github.com/letta-ai/letta/blob/ff19ffeafeb54bd2a7dc5d4a552f10191732a235/letta/functions/function_sets/base.py)

# 8. Concrete anti-patterns

1. **“When in doubt, extract” without a trust gate.** It maximizes recall but turns document and query injection into durable state. [Mem0](https://github.com/mem0ai/mem0/blob/4debc58a83377b18be81ae1e5969a300736b2fac/mem0/configs/prompts.py) [MINJA](https://arxiv.org/abs/2503.03704)
2. **Trusting everything in a user-role message.** Quotations, pasted documents, and another person’s text are not direct user assertions. [MINJA](https://arxiv.org/abs/2503.03704)
3. **Saving assistant recommendations as user preferences.** Mem0 V3 permits assistant recommendations but requires distinct attribution; collapsing them contaminates the user profile. [Mem0](https://github.com/mem0ai/mem0/blob/4debc58a83377b18be81ae1e5969a300736b2fac/mem0/configs/prompts.py)
4. **Delete-only contradiction handling.** The system may remove the old fact without preserving the replacement. [Mem0 classic prompt](https://github.com/mem0ai/mem0/blob/4debc58a83377b18be81ae1e5969a300736b2fac/mem0/configs/prompts.py)
5. **Treating distinct dated events as contradictions.** Graphiti’s Tuesday/Wednesday running example shows why temporal scope matters. [Graphiti](https://github.com/getzep/graphiti/blob/401c59a65bdeb22a44136901ff30231e6998a7fe/graphiti_core/prompts/dedupe_edges.py)
6. **Overwriting direct statements with inferred traits.** Mem0 forbids implicit attribute inference; LangMem requires confidence qualification. [Mem0](https://github.com/mem0ai/mem0/blob/4debc58a83377b18be81ae1e5969a300736b2fac/mem0/configs/prompts.py) [LangMem](https://github.com/langchain-ai/langmem/blob/29cbe41e58528f92e9efa773c12e15c47be3808c/src/langmem/knowledge/extraction.py)
7. **Using embeddings as the conflict detector.** Similarity finds candidates but does not distinguish duplicates, refinements, and contradictions; Graphiti uses a separate LLM resolution step. [Graphiti](https://github.com/getzep/graphiti/blob/401c59a65bdeb22a44136901ff30231e6998a7fe/graphiti_core/prompts/dedupe_edges.py)
8. **Using content hash as the sole idempotency mechanism.** Rephrases evade it, while identical text may describe distinct events. [Mem0](https://github.com/mem0ai/mem0/blob/4debc58a83377b18be81ae1e5969a300736b2fac/mem0/memory/main.py#L1000-L1032)
9. **Writing on every turn.** This creates redundant work, incomplete-context extraction, and unnecessary tokens; debounced background processing is the documented alternative. [LangMem](https://github.com/langchain-ai/langmem/blob/29cbe41e58528f92e9efa773c12e15c47be3808c/docs/docs/guides/delayed_processing.md)
10. **Letting a background worker rewrite whole profiles for narrow changes.** Letta separates precise replacement/insertion from full rethink for this reason. [Letta](https://github.com/letta-ai/letta/blob/ff19ffeafeb54bd2a7dc5d4a552f10191732a235/letta/functions/function_sets/base.py)
11. **Persisting relative time such as “recently.”** Letta and Mem0 V3 require grounding to observation dates. [Letta](https://github.com/letta-ai/letta/blob/ff19ffeafeb54bd2a7dc5d4a552f10191732a235/letta/prompts/system_prompts/sleeptime_v2.py) [Mem0](https://github.com/mem0ai/mem0/blob/4debc58a83377b18be81ae1e5969a300736b2fac/mem0/configs/prompts.py)
12. **No abstention tests.** LongMemEval explicitly treats abstention as a core memory capability. [LongMemEval](https://arxiv.org/abs/2410.10813)
13. **No source evidence or provenance.** Without immutable source links, erroneous and poisoned memories cannot be audited or safely re-extracted. [MINJA](https://arxiv.org/abs/2503.03704) [Zep](https://arxiv.org/abs/2501.13956)
14. **Treating prompt wording as the security boundary.** Query-only and low-rate memory poisoning succeeded against systems where the attacker did not modify model weights. [MINJA](https://arxiv.org/abs/2503.03704) [AgentPoison](https://arxiv.org/abs/2407.12784)
15. **Shipping extractor changes without shadow replay.** Long-term-memory quality spans extraction, updates, temporal reasoning, and abstention, so aggregate answer accuracy alone cannot identify the regressed stage. [LongMemEval](https://arxiv.org/abs/2410.10813)

The strongest practical architecture is therefore: conservative trusted-source admission, high-recall structured extraction inside that boundary, deterministic policy filtering, temporal/versioned conflict resolution, transactional idempotent writes, and extractor-specific offline and shadow evaluation.
