I read this as deep product/UX research - I verified current first-party flows and translated the findings into a privacy-forward design for professor authoring and grading memory.

# User-facing AI memory and personalization

**Research date:** 2026-08-11  
**Scope note:** Product UIs roll out by account, plan, administrator, and region. The flows below describe publicly documented behavior; labels may differ during staged rollouts. Privacy analysis is product guidance, not legal advice.

## Executive recommendation

For a Korean university exam platform, do **not** copy the dominant consumer pattern of silently inferring and immediately applying durable memories. Use a hybrid:

1. **Explicitly seed** a small professor profile during onboarding.
2. **Observe silently but write visibly:** infer candidates from repeated behavior, but require approval for consequential grading preferences.
3. **Auto-save only low-risk presentation preferences**, always with an inline notice and undo.
4. **Attach provenance, scope, and effective date** to every memory.
5. **Separate professor-, course-, and exam-level memory** to prevent preference leakage.
6. **Never apply learned preferences directly to final grades.** Use them to configure drafts and recommendations that the professor reviews.
7. Provide one stable control center: **Settings → AI personalization → Professor profile**, with view, edit, pause, reset, export, retention, and activity history.

This follows established human-AI guidance to disclose system capabilities, make contextually relevant suggestions, support efficient correction, and expose uncertainty rather than pretending the system is infallible ([Microsoft Human-AI Interaction Guidelines](https://www.microsoft.com/en-us/research/project/guidelines-for-human-ai-interaction/); [Google PAIR: Explainability and Trust](https://pair.withgoogle.com/guidebook-v2/chapter/explainability-trust/)).

# 1. Concrete product patterns shipped today

## 1.1 ChatGPT

### In-chat flow

1. The user states a durable preference or personal fact, either explicitly (“Remember that…”) or during ordinary conversation.
2. ChatGPT may save it and renders a small inline **“Memory updated”** notice beneath the response.
3. The notice acts as lightweight write disclosure rather than an interrupting confirmation dialog.
4. Users can ask “What do you remember about me?”, tell ChatGPT to forget or update something, or open the settings manager.

OpenAI distinguishes **saved memories** from **reference chat history**: saved memories are durable facts maintained separately from chat history, while reference chat history allows responses to use relevant information from previous conversations ([OpenAI Memory FAQ](https://help.openai.com/en/articles/8590148-memory-faq); [OpenAI, “Memory and new controls for ChatGPT”](https://openai.com/index/memory-and-new-controls-for-chatgpt/)).

### Settings flow

`Avatar/menu → Settings → Personalization`

The screen exposes separate controls for:

- **Reference saved memories**
- **Reference chat history**
- **Manage memories**
- **Temporary Chat** as an entry point outside settings for conversations that should neither use nor update memory

`Manage memories` opens a list where users can inspect and delete individual saved memories or delete all. Turning memory off does **not** itself delete already stored memories. Fully removing a fact may require deleting both the saved memory and the chat in which it appeared because saved memory and chat history are separate stores ([OpenAI Memory FAQ](https://help.openai.com/en/articles/8590148-memory-faq)).

### Empty and disabled states

A new or cleared account presents an empty manager explaining that remembered details will appear as ChatGPT learns them. With memory disabled, ChatGPT continues to work without using or creating saved memories. Temporary Chat offers a one-session clean slate without changing the global setting ([OpenAI Memory FAQ](https://help.openai.com/en/articles/8590148-memory-faq)).

### Control coverage

| Action | ChatGPT |
|---|---|
| View | Ask in chat; Manage memories list |
| Add/update | Natural-language instruction |
| Direct text edit in manager | Generally no; update conversationally |
| Delete one/all | Yes |
| Pause without deletion | Turn reference controls off |
| Per-chat exclusion | Temporary Chat |
| Provenance | Not normally exposed per saved-memory item |
| Export | Account data export exists, but memory-specific portability is less explicit than Claude’s |
| Undo write | Notice provides awareness, but no consistently documented one-click inline undo |

**Design lesson:** ChatGPT minimizes interruption well, but the separation between saved memory and chat-derived personalization makes complete deletion conceptually difficult.

## 1.2 Claude

Claude now documents both an improved memory experience and a legacy experience during migration. In the improved version, the primary entry is `Settings → Memory`; legacy accounts use `Settings → Capabilities` ([Claude memory help](https://support.claude.com/en/articles/11817273-use-claude-s-chat-search-and-memory-to-build-on-previous-context)).

### Initial setup

1. Open `Settings → Memory`.
2. Enable **Generate memory from chats**.
3. Claude builds memory from conversation history.
4. Memory is separated by project: each project has its own memory space and summary, while non-project chats occupy a separate scope.

Anthropic describes memory as focused on professional context: role, projects, working and communication style, technical preferences, and ongoing work ([Anthropic, “Bringing memory to Claude”](https://claude.com/blog/memory); [Claude memory help](https://support.claude.com/en/articles/11817273-use-claude-s-chat-search-and-memory-to-build-on-previous-context)).

### Memory manager

`Settings → Memory`

- Memories are grouped by category.
- Selecting an entry reveals its summary and details.
- **Tell Claude what to change or remove** provides conversational editing.
- **Delete** removes an individual memory.
- Users can update memory from ordinary chat by telling Claude what to remember.
- References to past chats can show citations linking to the source conversations.

This is currently the strongest mainstream pattern for combining inspectability, correction, and provenance ([Claude memory help](https://support.claude.com/en/articles/11817273-use-claude-s-chat-search-and-memory-to-build-on-previous-context)).

### Pause and reset

Disabling memory presents two semantically distinct actions:

- **Pause memory:** retain existing memory, but do not use it or create new memories; conversations during the pause are not later backfilled.
- **Reset memory:** permanently remove all ordinary and project memories.

That distinction is clearer than a generic off toggle because it explains whether stored data remains ([Claude memory help](https://support.claude.com/en/articles/11817273-use-claude-s-chat-search-and-memory-to-build-on-previous-context)).

### Incognito and export

A ghost icon starts **Incognito chat**. The UI gains a black border and “Incognito chat” label; these conversations neither use nor update memory and do not appear in user chat history. They may nevertheless be retained for 30 days by default, and Team/Enterprise incognito chats can appear in organizational exports, so “incognito” is not equivalent to immediate deletion ([Claude incognito help](https://support.claude.com/en/articles/12260368-use-incognito-chats)).

Claude also documents experimental memory import/export for migration or backup, and memory data is included in ordinary data exports ([Claude memory help](https://support.claude.com/en/articles/11817273-use-claude-s-chat-search-and-memory-to-build-on-previous-context)).

### Control coverage

| Action | Claude |
|---|---|
| View | Categorized manager |
| Edit | Conversational edit from entry or chat |
| Delete | Individual delete; full reset |
| Pause | Explicit pause preserving data |
| Per-chat exclusion | Incognito |
| Provenance | Citations to source chats when prior chats are referenced |
| Scope | Separate project memories |
| Export/import | Yes |
| Empty state | Setup/enable memory; rebuilt from history when requested |

## 1.3 Gemini

Gemini personalization has three conceptually separate inputs:

1. Memory of past Gemini chats
2. Connected Google app content and activity
3. Explicit instructions controlling how Gemini responds

These features require a personal Google Account and are not available for work, school, or supervised accounts in the documented flow ([Gemini personalization overview](https://support.google.com/gemini/answer/15637730?hl=en)).

### Past-chat memory flow

**Mobile:** `Menu → profile picture/initial → Personal Intelligence → Memory`  
**Web:** `Menu → Settings & help → Personal Intelligence → Memory`

The user can turn Memory on or off. Gemini does not expose a concise, independent fact list comparable to ChatGPT or Claude. Instead, users inspect and delete source conversations in **Gemini Apps Activity**. To determine whether memory affected a response, Google explicitly suggests asking Gemini, “Did you use any info from past chats?” ([Gemini past-chat memory help](https://support.google.com/gemini/answer/16598469?hl=en)).

### Correction and deletion

- Correct a mistaken inference directly in chat.
- To remove remembered information, delete every chat containing it from Gemini Apps Activity.
- For information originating in a connected app, delete relevant chats **and** disconnect or update the source app; doing only one may leave another path by which the information can be reused.
- Changes in connected sources may take days to affect personalization.

This is powerful but places substantial source-tracing burden on users ([Gemini past-chat memory help](https://support.google.com/gemini/answer/16598469?hl=en)).

### Explicit instructions

`Settings → Instructions for Gemini` allows users to define stable response preferences separately from inferred chat memory ([Gemini instructions help](https://support.google.com/gemini/answer/16598625?hl=en)).

### Activity, retention, and temporary chats

Gemini Apps Activity supports review, deletion, and configurable auto-deletion. Google documents an 18-month default activity retention option, changeable to 3 months, 36 months, or indefinite. Temporary chats are not used to improve Google AI with human review, though Google still processes and temporarily retains them for service and safety purposes. Google Takeout provides account-level export ([Gemini Privacy Hub](https://support.google.com/gemini/answer/13594961?hl=en); [Google Takeout](https://takeout.google.com/)).

### Control coverage

| Action | Gemini |
|---|---|
| View discrete inferred facts | No strong first-class list |
| Edit | Correct in conversation; edit explicit instructions |
| Delete | Delete source chats/activity |
| Pause | Turn Memory off |
| Per-chat exclusion | Temporary chat |
| Provenance | Ask whether past chats were used; no universal per-fact ledger |
| Export | Google Takeout |
| Empty state | Personalization overview/instructions setup |
| Key weakness | Complete deletion can require tracing chats and connected apps |

## 1.4 Microsoft 365 Copilot

Microsoft 365 Copilot combines:

- **Saved memories**
- Details inferred from **chat history**
- **Custom instructions**

Microsoft documents enhanced personalization as enabled by default unless an administrator disables it; saved memory is also on by default for eligible users ([Microsoft admin documentation](https://learn.microsoft.com/en-us/microsoft-365/copilot/copilot-personalization-memory); [Manage Copilot Memory](https://support.microsoft.com/en-us/Microsoft-365-Copilot/manage-copilot-memory-in-microsoft-365-copilot)).

### In-chat flow

When Copilot identifies a useful preference, it automatically saves it and displays **“Memory updated.”** Microsoft gives work-oriented examples such as role, recurring tasks, skills, and preferred reporting tools. Related memories may be merged, superseded, or removed by Copilot ([Manage Copilot Memory](https://support.microsoft.com/en-us/Microsoft-365-Copilot/manage-copilot-memory-in-microsoft-365-copilot)).

### Manager flow

`Copilot Chat → … Settings and more → Chat settings → Personalization → Saved memories → Manage saved memories`

The pane supports:

- Delete one memory
- Delete all memories
- Turn saved memory off

Turning saved memory off stops its application but does not delete stored entries. Chat-history inferences use a separate control ([Manage Copilot Memory](https://support.microsoft.com/en-us/Microsoft-365-Copilot/manage-copilot-memory-in-microsoft-365-copilot)).

### Full deletion and enterprise controls

Deleting a chat does not delete saved memories generated from it. Fully removing a detail can require deleting the saved memory and disabling/deleting chat-history personalization. If chat-history personalization is re-enabled within 30 days, inferred details may be recreated from retained chats ([Copilot personalization help](https://support.microsoft.com/en-us/Microsoft-365-Copilot/personalize-what-microsoft-365-copilot-remembers)).

Administrators can disable enhanced personalization, discover/export/delete memory through Microsoft Purview and Graph tooling, but documented Purview retention labels do not automatically govern Copilot memory, and memory actions do not currently generate Purview audit entries ([Microsoft admin documentation](https://learn.microsoft.com/en-us/microsoft-365/copilot/copilot-personalization-memory)).

### Control coverage

| Action | Microsoft 365 Copilot |
|---|---|
| View | Saved-memory pane |
| Edit | Usually update by chat; custom instructions separately editable |
| Delete | One/all |
| Pause | Saved-memory and chat-history controls |
| Per-chat exclusion | Temporary chat |
| Provenance | Limited in end-user manager |
| Export | User instructions manually; enterprise memory through DSR/admin tooling |
| Default | On unless user/admin disables |
| Key weakness | Multiple stores and retention semantics complicate complete deletion |

## 1.5 Notion AI / Notion Agent

Notion’s current Agent blends explicit instructions with conversational learning rather than presenting a conventional “memory database.”

### Entry points

- Circular Notion AI face in the lower-right corner
- Notion AI tab in the sidebar
- Hover over the AI face → **Personalize**

The Personalize flow supports:

- Name and visual accessory
- An editable **instructions page** for tone, workflows, and quirks
- Reusable **skills** for recurring prompts
- Conversational learning from facts such as reporting relationships, priorities, style, and workflow

Notion says the Agent “picks things up as you chat” and remembers style and workflows over time ([Notion, “Get started with your personal Agent”](https://www.notion.com/help/guides/get-started-with-your-personal-agent-in-notion)).

### Control model

The instructions page is a strong, inspectable source of truth because it is ordinary editable Notion content. However, the public flow does not document a granular inferred-memory ledger, per-write notices, provenance, confidence, pause/reset semantics, or memory-specific export comparable to Claude. Notion instead emphasizes workspace context, connected-tool search, reusable skills, and user-authored instructions ([Notion Agent guide](https://www.notion.com/help/guides/get-started-with-your-personal-agent-in-notion); [Notion AI security practices](https://www.notion.com/help/notion-ai-security-practices)).

**Design lesson:** an editable “profile page” is understandable and portable, but silently learned details still need a separate review surface if used for consequential decisions.

# 2. Consent, transparency, and privacy implications

## 2.1 A professor preference profile is personal data

A profile such as “Professor Kim usually gives partial credit for correct methodology,” “prefers difficult distractors,” or “writes terse feedback” relates to an identifiable professional. Professional context does not remove it from personal-data law. Under GDPR, profiling includes automated processing used to evaluate or predict aspects such as work performance, preferences, behavior, reliability, or location ([GDPR Articles 4 and 6](https://eur-lex.europa.eu/eli/reg/2016/679/oj/eng); [EDPB profiling guidance](https://www.edpb.europa.eu/documents/guideline/automated-decision-making-and-profiling_en)).

Under Korea’s PIPA, information that identifies or can reasonably be combined to identify an individual is protected; an account-linked professor profile therefore requires a defined purpose, appropriate legal basis, retention policy, safeguards, and data-subject controls ([PIPC English law portal](https://www.pipc.go.kr/eng/user/lgp/law/lawDetail.do)).

## 2.2 Consent is not just a toggle

If consent is the legal basis in Korea, the collection notice should separately and clearly identify:

- Purpose of collection/use
- Data items collected or inferred
- Retention period
- The right to refuse
- Any disadvantage caused by refusal

Avoid bundling optional AI personalization into acceptance of the core exam platform. EDPB guidance similarly warns against deceptive interface patterns that steer users toward privacy-invasive choices ([PIPC law portal](https://www.pipc.go.kr/eng/user/lgp/law/lawDetail.do); [EDPB deceptive-pattern guidance](https://www.edpb.europa.eu/public-consultations/guidelines-32022-on-dark-patterns-in-social-media-platform-interfaces-how-to_en)).

**Recommended Korean default:** opt-in for automatic observation and inferred profile creation. Explicit preferences entered by the professor can be stored as necessary to provide the requested feature, but the platform should still explain retention and reuse. Do not infer consent merely because the professor used an AI authoring tool once.

## 2.3 Opt-in versus opt-out in existing products

- Claude’s memory-generation feature is explicitly enabled by the user, although past-chat search may be enabled by default once available; enterprise owners can control organization availability ([Claude memory help](https://support.claude.com/en/articles/11817273-use-claude-s-chat-search-and-memory-to-build-on-previous-context)).
- Microsoft 365 Copilot enhanced personalization and saved memories are documented as on by default unless disabled by the tenant or end user ([Microsoft admin documentation](https://learn.microsoft.com/en-us/microsoft-365/copilot/copilot-personalization-memory)).
- Gemini requires eligible account settings such as Keep Activity and exposes a Memory toggle; its personalization features are unavailable on documented work/school accounts ([Gemini personalization overview](https://support.google.com/gemini/answer/15637730?hl=en); [Gemini memory help](https://support.google.com/gemini/answer/16598469?hl=en)).
- ChatGPT provides separate saved-memory and chat-history controls; OpenAI used explicit opt-in prompts when expanded chat-history memory reached the EEA, UK, Switzerland, Norway, Iceland, and Liechtenstein ([OpenAI memory announcement](https://openai.com/index/memory-and-new-controls-for-chatgpt/)).
- Notion exposes explicit instructions but also describes passive learning as users chat, without a similarly detailed public memory-control flow ([Notion Agent guide](https://www.notion.com/help/guides/get-started-with-your-personal-agent-in-notion)).

These differences reflect product and rollout choices, not a universal rule that a particular jurisdiction always mandates consent for every memory implementation.

## 2.4 Regional design

### EEA

GDPR requires a lawful basis, purpose limitation, data minimization, storage limitation, transparency, security, and data-subject rights. If the system obtains preferences by observing behavior rather than directly asking, Article 14 transparency may apply in addition to Article 13. A DPIA may be required if profiling is systematic and likely to create high risk ([GDPR Articles 5, 6, 13, 14, 25 and 35](https://eur-lex.europa.eu/eli/reg/2016/679/oj/eng); [European Commission: data protection by design/default](https://commission.europa.eu/law/law-topic/data-protection/information-business-and-organisations/obligations/what-does-data-protection-design-and-default-mean_en)).

### UK

The UK GDPR retains comparable access, rectification, erasure, restriction, portability, objection, and automated-decision protections. The ICO recommends embedding data minimization and privacy-friendly defaults in product design rather than relying on policy text after launch ([ICO individual rights](https://ico.org.uk/for-organisations/uk-gdpr-guidance-and-resources/individual-rights/individual-rights/); [ICO data protection by design/default](https://ico.org.uk/for-organisations/uk-gdpr-guidance-and-resources/accountability-and-governance/guide-to-accountability-and-governance/data-protection-by-design-and-by-default/)).

### South Korea

PIPA provides rights to access, correction/deletion, and suspension of processing. The amended law also includes data-transmission rights subject to statutory and decree-defined applicability, so a good product should offer export even where the legal portability obligation may not apply to every controller. Article 37-2 provides protections concerning solely automated decisions that materially affect rights or obligations; retaining a grading preference alone is unlikely to trigger that rule, but automatically assigning consequential grades could ([PIPC law portal](https://www.pipc.go.kr/eng/user/lgp/law/lawDetail.do); [PIPC announcement on amended PIPA](https://pipc.go.kr/eng/user/ltn/new/noticeDetail.do?bbsId=BBSMSTR_000000000001&nttId=2434)).

### Cross-border processing

A Korean university should disclose the processor, model provider, storage region, cross-border destination, transferred data, purpose, retention, and withdrawal route where applicable. Prefer a contract and architecture in which the university controls the profile and sends only task-relevant preferences to the model, rather than allowing a model vendor to maintain an independent behavioral profile.

## 2.5 Deletion and portability semantics

A defensible delete operation must cover:

1. The normalized memory record
2. Embeddings/index entries
3. Generated summaries and caches
4. Links to source events
5. Downstream model-provider state where contractually applicable
6. Backups according to a documented expiration schedule
7. Re-learning from still-retained source material

ChatGPT, Gemini, and Copilot demonstrate why this matters: deleting a conversation and deleting a saved or inferred memory are not necessarily the same action ([OpenAI Memory FAQ](https://help.openai.com/en/articles/8590148-memory-faq); [Gemini memory help](https://support.google.com/gemini/answer/16598469?hl=en); [Copilot personalization help](https://support.microsoft.com/en-us/Microsoft-365-Copilot/personalize-what-microsoft-365-copilot-remembers)).

Export should use a documented machine-readable format such as JSON or CSV and include value, category, scope, status, provenance, creation/update timestamps, effective date, and confidence. GDPR portability applies to qualifying data provided by the user and processed automatically on consent or contract; access rights are broader than portability rights ([GDPR Articles 15 and 20](https://eur-lex.europa.eu/eli/reg/2016/679/oj/eng)).

# 3. Trust patterns

## 3.1 Three write modes

| Memory class | Example | Recommended write behavior |
|---|---|---|
| Explicit | “Always use 5 answer options” | Save immediately; inline notice + undo |
| Low-risk inferred | Frequently selects Korean-first bilingual output | Offer one-click save after repeated evidence |
| Consequential inferred | Usually awards 30% partial credit for method | Require preview and explicit approval |

Mainstream assistants commonly write silently with a small notice, but a grading platform has a higher consequence level. Human-AI guidance recommends making it easy to invoke, dismiss, correct, and learn from AI behavior and to scope behavior according to context ([Microsoft Human-AI Interaction Guidelines](https://www.microsoft.com/en-us/research/project/guidelines-for-human-ai-interaction/)).

## 3.2 Provenance

Every memory detail view should show:

> **Partial-credit preference**  
> Award method credit when the final numerical answer is wrong.  
> **Scope:** Calculus II  
> **Learned from:** Midterm grading, Exam MATH-204-2026-M1, 2026-03-02  
> **Evidence:** Applied in 18 of 21 matching responses  
> **Status:** Professor-approved on 2026-03-04

Claude’s past-chat citations demonstrate that users can be shown the source rather than receiving an opaque assertion ([Claude memory help](https://support.claude.com/en/articles/11817273-use-claude-s-chat-search-and-memory-to-build-on-previous-context)). Do not reveal student names or answer text in a global professor profile; link to an access-controlled aggregate/source view.

## 3.3 Confidence

Show confidence only when it can be explained:

- **Confirmed** — explicitly entered or approved by the professor
- **Likely** — repeated consistent behavior with enough evidence
- **Tentative** — sparse or conflicting evidence

Avoid naked percentages such as “82% confident” unless users can understand the denominator and evidence. Google PAIR recommends matching explanations to user goals and avoiding explanations that create unjustified trust ([Google PAIR: Explainability and Trust](https://pair.withgoogle.com/guidebook-v2/chapter/explainability-trust/)).

Only **Confirmed** memories should automatically configure grading behavior. Likely and Tentative entries should remain suggestions.

## 3.4 Undo and history

After a write:

> `Preference saved for Calculus II: “Use 5-option multiple choice.”`  
> **Undo** · **View profile**

Undo should reverse the write immediately and prevent the same source event from recreating it. The detail view should retain an audit history of who approved, edited, paused, or deleted a preference. This improves on “Memory updated” notices that disclose a write but may require navigation to correct it.

# 4. Failure UX

## Wrong memory

Provide correction at the point of use:

> “I used your Calculus II preference: award method credit up to 30%.”  
> **Use for this exam only** · **Change preference** · **Don’t use here**

“Change preference” should open an inline editor with scope choices rather than forcing navigation to settings.

## Over-personalization

Every generation or grading-assistance panel should include:

- **Personalization used:** 3 preferences
- Expandable list of applied preferences
- **Regenerate without personalization**
- **Use platform defaults**
- **Pause for this exam**

Users need to understand why a result changed and recover without deleting their entire profile. Exposing relevant factors while retaining human control follows Google’s explainability guidance and Microsoft’s recommendation to support efficient correction and dismissal ([Google PAIR](https://pair.withgoogle.com/guidebook-v2/chapter/explainability-trust/); [Microsoft Human-AI Guidelines](https://www.microsoft.com/en-us/research/project/guidelines-for-human-ai-interaction/)).

## Contradictory behavior

When new behavior conflicts with a confirmed preference:

> “For three recent exams you used 4 options, but your confirmed profile says 5. Update the Calculus II preference?”

Actions:

- Keep 5
- Change to 4
- Varies by exam — ask each time
- Stop learning this preference

Never silently overwrite a professor-approved grading rule.

## Stale preference

Use validity controls:

- “Valid from Spring 2026”
- “Review next semester”
- “Course ended — archive course preferences?”
- “Last applied 14 months ago”

Do not infer that recency automatically means correctness; ask before replacing confirmed rules.

## Unsafe or sensitive inference

Do not create memories about health, political views, union activity, religion, disability, alleged misconduct, or student-specific characteristics from professor behavior. GDPR treats several such categories as specially protected, and PIPA separately regulates sensitive information ([GDPR Article 9](https://eur-lex.europa.eu/eli/reg/2016/679/oj/eng); [PIPC law portal](https://www.pipc.go.kr/eng/user/lgp/law/lawDetail.do)).

# 5. Onboarding and cold start

## Recommended progressive disclosure

### First encounter

Use a compact banner in the authoring tool:

> **Make AI drafts match how you assess**  
> Save question and grading preferences to your private professor profile. Nothing is learned until you enable it. You review grading-related suggestions before they are saved.  
> **Set up profile** · **Not now** · **Learn how data is used**

Do not put a mandatory questionnaire in account registration; personalization becomes meaningful only when the professor encounters AI authoring or grading.

### Short seed questionnaire

Keep setup to five high-value questions:

1. Primary language: Korean / English / bilingual
2. Typical question mix: multiple choice / short answer / essay / numerical
3. Default difficulty distribution
4. Feedback style: concise / explanatory / Socratic
5. Partial-credit posture: none / rubric-only / method credit / varies by course

Each item needs **Skip** and **Varies by course**. Then let the professor import an existing exam or rubric to generate **reviewable candidates**, not committed memories.

Questionnaire seeding solves cold start; observation catches tacit preferences. Pure observation is slow and can misread institutional constraints as personal preference, while pure questionnaires capture stated rather than demonstrated behavior.

### First-value moment

Immediately produce a preview:

> “Based on your setup, this draft uses Korean stems, five answer options, and a 20/50/30 easy-medium-hard distribution.”

Show **Edit for this exam** and **Save as course default** separately.

### Ongoing learning

After repeated behavior, surface at most one candidate at a natural stopping point:

> “You changed feedback to one concise sentence in 8 recent cases. Save this for Calculus II?”  
> **Save** · **No** · **Never suggest this**

Avoid interrupting each grading action.

# 6. Education-domain prior art

## Gradescope

Gradescope’s AI-assisted grading groups similar answers. The instructor reviews or modifies answer groups, creates/applies rubric items, and grades a group consistently rather than accepting opaque individualized grades. This is valuable prior art for **human-approved pattern extraction** and batch consistency ([Gradescope, “AI-assisted grading and answer groups”](https://guides.gradescope.com/hc/en-us/articles/24838908062093-AI-assisted-grading-and-answer-groups)).

**Memory implication:** remember professor-approved grouping and rubric conventions, not student-level outcomes.

## Turnitin

Turnitin Feedback Studio provides reusable **QuickMarks**, rubrics, grading forms, inline comments, and links between comments and rubric criteria. These are explicit instructor-created artifacts rather than passively inferred personality profiles ([Turnitin Feedback and QuickMarks](https://guides.turnitin.com/hc/en-us/sections/35394994635789-Feedback-and-QuickMarks); [Turnitin rubrics and grading forms](https://guides.turnitin.com/hc/en-us/sections/22045123336845-Rubrics-and-grading-forms)).

**Memory implication:** recurring comments, rubric structures, criterion wording, and feedback tone are high-value, inspectable seeds.

## Khanmigo teacher tools

Khanmigo generates standards-aligned lesson plans, quiz questions, answer keys, rubrics, activities, student groupings, and concise or multilingual communications. Khan Academy explicitly positions question and rubric generation as ways to reduce preparation workload ([Khanmigo for Teachers](https://www.khanmigo.ai/teachers)).

**Memory implication:** professors benefit when the system remembers subject, question format, standards or learning objectives, explanation depth, language, and rubric style.

## Canvas / IgniteAI

Canvas IgniteAI embeds AI into existing teaching workflows and advertises course-content-grounded generation, quizzes, assignments, rubrics, feedback, discussion insights, and grading assistance. Instructure emphasizes institutional opt-in, transparency through “AI Nutrition Facts,” and educator control ([Instructure IgniteAI](https://www.instructure.com/igniteai); [Canvas AI feature overview](https://community.instructure.com/en/kb/articles/664510-what-are-the-available-ai-features-in-canvas)).

**Memory implication:** integrate personalization where professors already author and grade; do not create a detached chatbot-only workflow.

## Coursera

Coursera’s author tooling uses AI to assist course building, assessment authoring, translations, simulations, and interactive instructional experiences. Its pattern is course-context generation rather than a public, granular instructor-memory manager ([Coursera AI-powered innovations](https://blog.coursera.org/new-ai-powered-innovations-on-coursera/); [Coursera Course Builder](https://blog.coursera.org/coursera-launches-course-builder/)).

**Memory implication:** scope retained preferences to a course or course family, with explicit promotion to an institution-independent professor default.

## What instructors likely want remembered

This list is a synthesis of the recurring affordances in Gradescope, Turnitin, Khanmigo, Canvas, and Coursera—not a claim that every instructor wants every item.

### Exam authoring

- Course and subject vocabulary
- Korean/English/bilingual language policy
- Question-type mix
- Number of options and distractor style
- Difficulty distribution
- Learning-objective or taxonomy balance
- Preferred notation, units, and rounding
- Whether negative wording is allowed
- Desired stem and explanation length
- Repeated formatting conventions
- Topics to include, avoid, or not repeat
- Accessibility conventions

### Rubrics and grading

- Criterion structure and point granularity
- Partial-credit rules
- Accepted equivalent methods or answers
- Significant-figure and unit treatment
- Common error categories
- Whether one error should cascade through later steps
- Feedback tone and length
- Reusable comments/QuickMarks
- Borderline-case escalation rules
- Anonymity and moderation preferences
- Whether AI may draft feedback, propose scores, or only flag inconsistencies

### What should not become professor memory

- Student-specific ability, disability, conduct, or predicted performance
- Unapproved conclusions about professor strictness or fairness
- Individual grade outcomes
- Temporary accommodations
- One-off exam constraints
- Sensitive communications
- Preferences inferred from actions performed by teaching assistants unless attributed and approved

# 7. Recommended product architecture and flows

## Scope hierarchy

```text
Institution policy (locked)
└── Professor defaults
    └── Course preferences
        └── Exam overrides
            └── Question/rubric override
```

Lower levels may override higher ones only where institution policy permits. Every generated result should identify the effective preferences and their scopes.

## A. Enable and seed personalization

```mermaid
flowchart TD
    A[Professor opens AI authoring] --> B[Personalization explainer]
    B -->|Not now| C[Use platform defaults]
    B -->|Set up| D[Consent and data-use summary]
    D --> E{Enable observation-based learning?}
    E -->|No| F[Explicit preferences only]
    E -->|Yes| G[Explicit + reviewable inferred candidates]
    F --> H[Five-question profile]
    G --> H
    H --> I[Optional import: prior exam or rubric]
    I --> J[Preview extracted candidates]
    J --> K{Professor reviews each item}
    K -->|Approve| L[Save with scope and provenance]
    K -->|Edit| M[Edit value/scope, then save]
    K -->|Reject| N[Discard; do not relearn from same source]
    L --> O[Generate first personalized draft]
    M --> O
    N --> O
```

## B. Low-risk inline write

```mermaid
flowchart LR
    A[Professor explicitly requests a durable preference]
    --> B[Save scoped memory]
    --> C[Inline notice: Preference saved]
    C --> D[Undo]
    C --> E[View professor profile]
```

Use this only for explicit or low-risk settings such as language, formatting, or option count.

## C. Consequential inferred preference

```mermaid
flowchart TD
    A[Repeated grading behavior detected] --> B[Create candidate, not active memory]
    B --> C[Aggregate evidence and remove student identifiers]
    C --> D[Review card after grading session]
    D --> E{Professor decision}
    E -->|Approve| F[Confirmed course preference]
    E -->|Edit| G[Save corrected preference]
    E -->|Not now| H[Snooze]
    E -->|Never learn this| I[Suppress category]
```

## D. Application during authoring or grading

```mermaid
flowchart TD
    A[Open exam or grading session] --> B[Resolve institution, professor, course, exam rules]
    B --> C[Show personalization summary]
    C --> D[Generate draft/recommendation]
    D --> E[Label applied preferences and provenance]
    E --> F{Professor action}
    F -->|Accept/edit| G[Continue workflow]
    F -->|Without personalization| H[Regenerate using defaults]
    F -->|Preference is wrong| I[Inline correction]
    I --> J{Apply where?}
    J -->|This item only| K[Temporary override]
    J -->|This exam| L[Exam override]
    J -->|Course default| M[Update confirmed memory]
```

Final grades remain subject to professor confirmation.

## E. Memory control center

`Profile → Settings → AI personalization → Professor profile`

### Header

- Status: **On / Paused**
- “AI used 6 preferences in your last exam”
- **Pause**
- **Export**
- **Delete all**
- Link to privacy and retention details

### Tabs

1. **Confirmed**
2. **Suggestions**
3. **Courses**
4. **Activity**
5. **Data controls**

### Memory row

```text
[Confirmed] Partial credit: up to 30% for correct method
Scope: Calculus II
Source: Midterm grading · 2026-03-02
Last used: Final draft · 2026-06-11
[Edit] [Pause] [Delete]
```

### Empty states

- **Never enabled:** “AI currently uses platform defaults. Set up a profile to tailor drafts.”
- **Enabled, no memories:** “No saved preferences yet. Add one or import a prior exam.”
- **No suggestions:** “Nothing to review. AI will suggest only repeated patterns.”
- **Paused:** “Your profile is retained but is not being used or updated.”
- **After reset:** “All profile memories have been deleted. Existing exams and grades were not changed.”

## F. Pause, reset, and delete

Copy must distinguish:

- **Pause:** retain data; do not use, infer, or backfill from paused activity.
- **Delete one:** erase the selected memory and derived indexes; offer optional source deletion where appropriate.
- **Reset profile:** erase all memories and candidates; preserve authored exams and required academic records.
- **Delete source activity:** remove eligible AI-interaction logs subject to institutional retention requirements.
- **Stop relearning:** prevent retained source events from recreating deleted memories.

Claude’s pause/reset distinction is the clearest product precedent ([Claude memory help](https://support.claude.com/en/articles/11817273-use-claude-s-chat-search-and-memory-to-build-on-previous-context)).

# 8. Launch policy

## Initial release

- Opt-in
- Professor-owned profile
- Course-scoped by default
- Explicit preferences plus reviewed candidates
- No student-specific memory
- No autonomous grade assignment
- Inline write notice with undo
- Provenance and effective date
- Pause, delete, reset, and JSON export
- Separate source-activity retention controls
- Institution administrator can disable the feature but cannot silently edit an individual professor’s pedagogical profile

## Later expansion criteria

Allow automatic saving for a preference category only after evidence shows that:

1. Errors are easy to detect before harm.
2. Undo fully removes the preference.
3. The category cannot materially affect grades or student rights.
4. Professors understand the scope.
5. Rejected suggestions are not repeatedly resurfaced.
6. Audit and deletion behavior has been tested end to end.

## Success metrics

Measure:

- Profile enablement after informed disclosure
- Candidate approval/edit/rejection rates
- Undo and incorrect-memory rates
- Regeneration-without-personalization rate
- Time saved in authoring and rubric creation
- Grade-change rate after AI recommendations
- Cross-course leakage incidents
- Deletion completion time
- Percentage of active memories with valid provenance
- Professor-reported control and trust

Do not optimize for number of memories stored. The product goal is fewer repeated corrections and more consistent drafts, not maximum profiling.
