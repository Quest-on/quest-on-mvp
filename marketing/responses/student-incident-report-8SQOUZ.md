## 1. 요약 (Executive Summary)

해당 학생의 시험 세션에 대한 데이터베이스 조사 결과, **외부 붙여넣기(external paste) 기록이 전혀 존재하지 않으며**, 답안 작성 이력(answer_history)은 **직접 타이핑(direct typing)의 명확한 증거**를 보여줍니다. 따라서 해당 학생의 답안이 "외부 붙여넣기"로 판정된 것은 **시스템 오류 또는 다른 학생/세션과의 혼동**으로 판단됩니다.

### 3.2 답안 작성 이력 — 직접 타이핑 증거 명확

`submissions.answer_history` 필드는 답안 작성 과정에서의 **모든 중간 상태**를 시간 순서대로 저장합니다. 이를 통해 "복사·붙여넣기"인지 "직접 타이핑"인지 판단할 수 있습니다.

#### 문항 1 (q_idx=0) — answer_history

| # | 시각 (UTC) | 답안 내용 | 길이 | 이전 대비 증가 |
|---|-----------|----------|------|--------------|
| 1 | 00:28:36 | `Team man` | 8 | — |
| 2 | 00:29:09 | `Team manager's actual performance is ` | 39 | +31 (33초) |
| 3 | 00:29:34 | `Team manager's actual performance is not fairness. ` | 51 | +12 (25초) |
| 4 | 00:30:36 | `...not fairness. It ` | 54 | +3 (62초) |
| 5 | 00:31:04 | `...Incorrect ` | 65 | +11 (28초) |
| 6 | 00:31:31 | `...Incorrect e` | 66 | +1 (27초) |
| 7 | 00:32:00 | `...Incorrect performance ` | 78 | +12 (29초) |
| 8 | 00:32:25 | `...performance ignore ` | 86 | +8 (25초) |
| 9 | 00:32:53 | `...ignore termin` | 92 | +6 (28초) |

**분석:**
- 각 수정 간격이 **25~62초**로, 사람이 직접 타이핑하는 속도와 일치합니다.
- 한 번에 대량의 텍스트가 삽입된 적이 없습니다. 모든 변경이 **소폭 증가(1~31자)**입니다.
- 문장 중간에 `It`을 넣었다가 지우고 `Incorrect`로 바꾸는 등, **실시간 문장 구성 과정**이 보입니다.
- 외부에서 복사한 완성된 문장이라면, 한 번에 수백 자가 삽입되어야 합니다.

**최종 답안:** `"Team manager's actual performance is not fairness. Incorrect performance ignore terminal values. "`
→ 문법적으로 불완전한 영어 문장입니다. 외부 문서에서 복사한 정제된 문장이 아닙니다.

### 3.3 "붉은 글씨/점" 렌더링 원인 분석

Quest-On 시스템은 교수(강사) 채점 화면에서 `FinalAnswerCard` 컴포넌트를 통해 답안을 렌더링합니다. 이 컴포넌트의 동작 방식은 다음과 같습니다:

1. **`paste_logs`가 존재할 때만** 하이라이트 기능이 작동합니다.
2. 외부 붙여넣기(`suspicious = true`)인 경우 **빨간색 배경(`bg-red-200`)**으로 텍스트를 강조합니다.
3. 내부 복사(AI 답변)인 경우 **파란색 배경(`bg-blue-200`)**으로 강조합니다.
4. 붙여넣기 후 수정된 경우 **옅은 빨간색 + 투명도 60% (`bg-red-100 opacity-60`)**로 표시됩니다.
5. 정규식 매칭에 실패할 경우, `paste_start`/`paste_end` 위치 기반으로 **근사 하이라이트**를 적용하여 "점"처럼 보이는 현상이 발생할 수 있습니다.

**해당 학생의 경우:**
- `paste_logs`가 **비어있으므로**, 위 하이라이트 기능은 **작동하지 않아야 합니다**.
- 따라서 교수님 화면에 "붉은 글씨/점"이 표시되었다면, 다음 중 하나로 추정됩니다:
  - **다른 학생의 답안**을 잘못 열람하신 경우
  - **브라우저 캐시/렌더링 오류**로 이전에 보던 다른 학생의 하이라이트가 남아있던 경우
  - **동일 시험의 다른 세션** 데이터가 잘못 로드된 경우

## 4. 결론

### 4.1 요청사항 1: 입력 로그 — 직접 타이핑 증명

**결론: 해당 학생은 직접 타이핑으로 답안을 작성했습니다.**

증거:
1. `paste_logs` 테이블에 **외부 붙여넣기 기록이 0건**입니다.
2. `answer_history`에 **순차적이고 점진적인 텍스트 증가 패턴**이 명확히 기록되어 있습니다.
3. 각 수정 간격이 **20~35초**로, 인간의 타이핑 속도와 일치합니다.
4. 최종 답안의 영어 문장이 **문법적으로 불완전**하여, 외부 문서에서 복사한 것이 아닙니다.

### 4.2 요청사항 2: 붉은 글씨/점 렌더링 원인

**결론: 시스템 오류 또는 세션 혼동으로 추정됩니다.**

증거:
1. 해당 학생의 세션에는 `paste_logs`가 없으므로, 시스템이 **자동으로 붉은 글씨를 표시할 수 없습니다**.
2. `FinalAnswerCard` 컴포넌트는 `paste_logs`가 있을 때만 하이라이트를 적용합니다.
3. 따라서 교수님 화면에 붉은 글씨/점이 보였다면, **다른 학생의 데이터가 잘못 표시된 것** 또는 **브라우저 캐시 문제**로 보입니다.

## 5. 권고사항

### 학생에게

1. **외부 붙여넣기 혐의는 근거가 없습니다.** 데이터베이스상 해당 세션에 붙여넣기 기록이 전혀 없습니다.
2. **답안 작성 이력이 직접 타이핑을 명확히 뒷받침합니다.** 시간 순서대로 점진적으로 작성된 기록을 교수님께 제출하실 수 있습니다.
3. **다만, 1번 문항의 답안이 매우 짧고(2문장), 3번 문항은 미제출 상태**이므로, 점수에 대한 이의는 "외부 붙여넣기"가 아닌 "답안의 질적 완성도" 측면에서 논의하시는 것이 적절합니다.

### 교수님께

1. 해당 학생의 "외부 붙여넣기" 판정은 **기술적 오류**로 확인되었습니다. 채점 시 이 부분은 불이익 근거에서 제외하시는 것이 타당합니다.
2. "붉은 글씨/점" 렌더링은 해당 학생의 세션이 아닌 **다른 세션의 데이터**가 표시된 것으로 보입니다. 동일 시험의 다른 학생 답안을 확인하실 때 브라우저 새로고침 후 재확인을 권장드립니다.
3. 채점 점수(1번 20점, 2번 30점, 3번 5점)는 답안의 질적 기준(루브릭)에 따른 것으로, 외부 붙여넣기 여부와 무관하게 판단하신 것으로 이해합니다.

### 시스템 개선

1. `paste_logs`와 `answer_history`를 교수 채점 화면에 함께 표시하여, **감지 기록과 실제 입력 이력을 교차 확인**할 수 있도록 개선.
2. 세션 전환 시 브라우저 캐시를 완전히 초기화하여, **이전 세션의 하이라이트 데이터가 남는 문제** 방지.
3. "부정행위 의심" 배너에 **세션 ID와 paste_logs 건수**를 함께 표시하여 혼동 방지.
