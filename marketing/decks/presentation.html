Supporting 6: 지원 테이블
핵심 5개 외에 운영과 기능 확장을 위한 테이블입니다
● exam_material_chunks
RAG 벡터 저장소 — 수업 자료를 청크 단위로 쪼개고 벡터 임베딩으로 변환해서 유사도 검색을 지원합니다
embedding vector(1536), content, file_url
● ai_events
AI API 사용량 및 비용 추적 — 모든 OpenAI 호출의 토큰 수, 비용, 지연시간을 기록합니다
model, tokens, estimated_cost_usd_micros, latency_ms
● student_profiles
학생 정보 저장 — 이름, 학번, 소속 학교 등 프로필 데이터를 관리합니다
student_id (unique), name, student_number, school
● exam_nodes
폴더/시험 트리 구조 — 강사가 시험을 폴더로 정리할 수 있는 재귀적 계층 구조입니다
parent_id (self FK), kind: 'folder'|'exam', sort_order
● questions
정규화된 문제 정의 — exams.questions JSON의 보조 테이블로, 개별 문제를 독립적으로 관리합니다
exam_id (FK), idx, type, prompt, ai_context
● audit_logs
감사 로그 — 모든 시스템 액션을 기록해서 문제 추적과 컴플라이언스를 지원합니다
action, user_id, target_id, details (JSONB)

설계 선택과 이유: 왜 이렇게 했을까요?
JSON questions를 JSON으로 저장
문제 개수, 순서, 구조가 시험마다 다릅니다. 별도 테이블로 정규화하면 JOIN이 복잡해지는 반면, JSON으로 저장하면 한 번의 조회로 시험 전체 데이터를 가져올 수 있습니다.

exams.questions JSON exams.rubric JSON
Hub sessions를 허브 테이블로
"학생이 시험을 치른다"는 행동이 핵심입니다. session 하나에 답안, 채팅, 점수가 모두 연결됩니다. 상태머신으로 흐름을 제어합니다.

not_joined → joined → waiting → in_progress → submitted
Vector pgvector로 유사도 검색
수업 자료를 800자 단위로 청킹하고 OpenAI text-embedding-3-small으로 1536차원 벡터를 생성합니다. 학생이 AI에게 질문하면 코사인 유사도로 관련 자료를 찾아 답변에 활용합니다.

vector(1536) cosine similarity
Stage 단계별 채점 (stage_grading)
채점을 chat, answer, feedback 3단계로 나눠서 JSON에 저장합니다. 정규화하면 3개 테이블이 더 필요하지만, 한 세션의 채점 결과를 한 번에 조회하기 위해 JSON을 선택했습니다.

{ chat: {score, comment}, answer: {score, comment}, feedback: {score} }
